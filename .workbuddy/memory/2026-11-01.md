## docs/视觉识别实现说明.md（新增）

- 定位：识别链路的**实现手册**，与应用目录 README（架构概览）分工不同——
  记模块边界、内部步骤、结果字段契约、改动影响矩阵、回滚边界。
- 已在 `docs/README.md` 的「文档总览」与「目录说明」登记。

写文档时逐条核对代码得到的结论（以后别再踩）：

- 依赖单向无环：`target_api → rectangle_center → contour_locator → rect_geometry`；
  `rect_geometry` 不 import 业务模块，可单文件回滚。
- 提案层与验证层的出画口径必须一致（`SEARCH_ALLOW_CLIPPED` ↔ `MAX_CLIPPED_EDGES`）：
  只放宽验证层，贴边候选在提案阶段就被丢，容忍等于白写。
- `_refine` 的兜底边必须经 `_verify(exempt_edges=...)` 豁免，否则"缺证据"被自己再拒一次，
  表现为救回来了却整帧失败。
- 结果 dict 有四个消费者：`aim_control`（u/v/raw/stage）、`draw_result`（quad/partial/circle_points）、
  `telemetry`（det_stage/det_fail/proposals）、`target_api`（包装字段）。改名不报错、只静默坏。
- `preview.py` 自身不读几何字段，绘制入口是 `rectangle_center.draw_result()`，由 `app_runtime` 调用。
- `_accept = _verify or _rescue`：搜索阶段的 rescue 是单次弱证据兜底，不是级联。

## 识别内核重写（v1.2.0 simple-rect）

决策（用户已确认四项）：原地重写 `rectangle_center.py`、删三个旧模块、中心取四点对角线交点、
无状态每帧全图、只留 `run_pc` + `diagnose_detect` 两个通用工具。

- 删除：`vision/contour_locator.py`、`rect_geometry.py`、`kalman_filter.py`；
  `tools/` 下 16 个依赖旧判据的回归脚本。`config.py` 识别段整段换成 `RECT_*`。
- 门禁：`check_pc.TESTS` 19 → 11 项，`build_single.MODULES` 23 → 20 个源文件；全绿 14 passed。

**最终形态（用户裁决，不要再自行加码）**：只保留 `RECT_MAX_AREA_RATIO` 上限。
凸性检查、对边长度比、对角线退化回退 bbox 中心——三项都不要。

1. 长宽比就是 `w/h`（正立外接框），**前提是靶纸横放**。实测：横放 0/12/25° 通过
   （aspect 1.43/1.26/1.14），35° 与竖放全部失败。这是约定的使用前提，不是缺陷；
   真出现竖放/大角度，改判据而不是抬参数。
2. 对角线无交点（四点共线）时本帧判失败（`fail_reason='degenerate'`），不拿 bbox 中心凑数。
3. `tools/example_api_usage.demo_frame` 必须横放（原竖放会被 w/h 拒），
   已改为 297×210 横向透视、宽高比约 1.35。

已知边界（方案性，调参无解）：遮挡/贴边→轮廓非凸；竖放或大角度倾斜→长宽比拒；
画面里更大的深色矩形会抢锁（需第四层亮度证据）。

## 结构约定（用户明确要求）

**类内不堆方法**：`RectangleCenterDetector` 只保存参数并编排，所有小功能都是模块级函数——
`to_gray_frame` / `blur_frame` / `binarize_frame` / `find_quad_candidates` / `select_largest` /
`fail_result` / `success_result` / `locate_result` / `finish_result`。
新增能力一律加模块函数，不要再往类里塞 `_xxx` 方法；`diagnose_detect.py` 直接调这些函数。

注意：`check_pc` 不验证识别效果，识别只能靠 `run_pc` 在真实帧上看。
`tools/real_board_frame.png` 上边被灰块遮住，是有效的困难样本，当前必然失败。
