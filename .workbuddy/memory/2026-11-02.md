## git 推送打通（环境，非代码）

现象：`git ls-remote` / `push` 失败 `schannel: InitializeSecurityContext failed:
CRYPT_E_NO_REVOCATION_CHECK (0x80092012)`。

根因：本机 GitHub 走 Watt Toolkit（SteamTools）本地 MITM 代理
`127.0.0.1:33373`（env `https_proxy` 强制），它签发的是自签根
`CN=SteamTools Certificate, O=BeyondDimension`；schannel 后端无法完成该证书的
吊销检查（离线 CRL），因此在握手阶段直接失败。

解法（已落全局配置，普通 `git push` 直接可用）：
- `http.sslBackend=openssl`：换成 OpenSSL 验证链。
- `http.sslCAInfo=C:/Users/CloudyRain/.git-ca-bundle.pem`：该文件 = certifi
  `cacert.pem` + SteamTools 根证书（两个 thumbprint，来自 CurrentUser/LocalMachine Root）。
- `http.schannelCheckRevoke` 无用（设 false 仍报同一错），已移除，不留垃圾配置。

注意：**不要**用 `GIT_SSL_NO_VERIFY=1` 长期推——上方案已保留完整证书校验。
SteamTools 证书 notAfter 2027-03-10 过期后需重导出该 bundle。
