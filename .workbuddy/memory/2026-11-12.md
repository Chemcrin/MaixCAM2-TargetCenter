# 2026-11-12

## 视觉引擎替换：ring_hole → GPT-Replay fast-perspective（v17）

按用户要求把 `GPT-Replay/maixcam2_rect_center` 的黑框算法移植回主轨，替换原环-洞链路，
云台闭环保持原样，靠 result 契约联动。

### 做了什么
- `vision/algo.py` 重写：只留纯函数（`order_quad` / `quad_diagonal_center` /
  `project_points` / `sample_points` / `profile_samples` / `refine_sample_points` /
  `valid_quad` / `poly_area` / `edge_lengths` / `deviation`）。原 ring_hole / hole_quad /
  prefilter_boxes 等全部退役。
- `vision/logic.py`：`RectangleCenterDetector` 换成"Otsu 提案 → 窄带带宽验证 → 四边梯度精修"，
  输出对齐主轨契约（valid/stage/u/v/raw_u/raw_v/quad/inner_quad/bbox/area/aspect/band/
  fail_reason/t_ms/build）。`LaserSpotDetector` / `GimbalAim` / `VisionControl` / 主循环未动。
- `config.py`：识别区换成 25 个新参数（SEARCH_WIDTH / BLACK_FRAME_MM / TARGET_*_MM /
  MIN_EDGE_* / RECT_ASPECT_* …），删除 21 个 ring_hole 与 ROI 跟踪旧参数。
- `tools/test_smoke.py` 按新判据重写：合成图带宽按物理比例生成；新增"中心=内框交点"、
  "带宽门"、"形状门"、"遮挡鲁棒"、"大半出画"五项。
- `tools/run_pc.py` 的 `--stage` 从 none/blur/binary 收紧到 none/binary。

### 移植时修掉的原版缺陷
1. **中心取外框**：GPT 原版 `_line_intersection_center(candidate["quad"])` 用的是检测到的
   轮廓（多为胶带外沿），胶带上下不等宽时偏半个带宽。改成 `inner_quad`（纸边）交点，
   透视用例误差从 3.5px 降到 0.5px。
2. **没有形状门**：原版正方框会被检出（实测 200×200 命中），补 `RECT_ASPECT_MIN/MAX`
   长短边比门，方形显示器/窗格回到"拒"的行为。

## 追加：板端观感差异排查（图传宽度 + 框显示语义）

用户拿 GPT-Replay 原版截图对照，质疑"移植后分辨率变低"。

- 根因一：`SHOW_STREAM_WIDTH` 沿用了 v16 的 240（为保 30fps），GPT 版默认 480。
  240 宽图传放大到窗口后必然发糊，**与识别分辨率无关**：相机 640×480，
  `SEARCH_WIDTH=320` 只作用于提案，`_verify`/`_refine` 全在全分辨率上跑。
  已改回 480（config 注释标明"追帧率再降回 240"）。
- 根因二：`draw_result` 把 `quad`（物理外推的胶带外沿）画成绿粗线。当检测器判成
  `kind="inner"`（锁到纸边）时，绿框会外扩一个 `BLACK_FRAME_MM`，看起来像"框飘了"，
  实际中心取自 `inner_quad` 交点、完全正确。已改为三条线各管一件事：
  绿=`detected_quad`（实测边）、青=`inner_quad`（纸边）、洋红=`quad`（外推外框）。
- 量化证据：像素级测量两张截图，图 1 的绿框比黑带外沿外扩 8~12px（截图尺度），
  与"外推 18mm"一致；图 2 的绿框基本贴外沿（它的 kind=outer）。
- 顺带发现：GPT 原版板端 `track 546.4ms`、FPS 1.6；我们这版 PC 跟踪态 0.74ms，
  板端未实测。
