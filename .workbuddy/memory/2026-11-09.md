## 视觉引擎第二次重写：降到 3.5ms/帧、42fps（fast-track-v8/v9）

用户三个诉求：晃动就丢锁、帧率个位数、逻辑不够优。定位后确认根因不是参数，
是"每帧在 640x480 全图上做边缘+轮廓+逐边采样"，而板上每次 Python 级 numpy
调用约 1ms —— **调用次数就是耗时**。

**新链路（五段，全部只调十来次 cv2/numpy）**
1. 降采样 1/2（INTER_AREA）；
2. 阈值 = 0.62 × 画面 90 分位亮度（分位数在 1/16 子采样上算），
   夹在 [max(45, p2+15), 160]；
3. `connectedComponentsWithStats` 一次拿全部块（不用 findContours 逐轮廓取外接框）；
4. 四道门挑环：面积 / 长短边比 1.05~2.6 / 填充率 0.03~0.70 /
   **四条边最弱一条的暗像素占比 ≥ 0.20**（这一条把"框住靶心的稀疏暗结构"排掉：
   环实测 0.27~0.45，窗棂/柜门缝只有 0.10）；
5. 定心：框心向外扫四条线找"亮→暗"跨越，取左右/上下弦中点。外接框中心会被
   阴影带偏（实测 bbox 心 7.7/5.9px vs 弦中点 3.8/2.3px），弦中点不需要任何
   单应或拟合。

**稳定性三件套（"晃动丢锁"的解药）**
- ROI 跟踪：锁定后只在上帧框的 1.35 倍范围内找，按速度外推；
- 抖动容错：抓不到就按速度外推继续输出最多 6 帧（RECT_HOLD_FRAMES），
  超过才 HOLD + 全图重搜；
- 跟踪门 0.45×框边长 + 速度限幅 2500px/s + dt≥4ms 才更新速度。最后这条是必须的：
  连拍两帧 dt≈0.2ms，速度除出天文数字，ROI 被甩飞，实测会锁到墙上别的东西。

**踩过的三个真 bug（都写进注释了）**
1. ROI 原点是原图坐标，却又乘了一次缩放系数 → 中心系统性偏一个 ROI 原点；
2. 尺寸容差按"上一帧"比 → 每帧可缩 45%，一路缩到纸面圆环上
   （250x180 → 114x112 → 50x52）；改成按"锁定尺寸"比，参考尺寸每帧最多跟随 2%；
3. stats["components"] 在 _detect 里被 _last_components(0) 覆盖 → 失败归因
   永远报 no_proposal。
