Step42 闭环步进驱动 / 42 导电滑环 —— 对当前项目的借鉴分析

结论一句话

两个仓库里只有 Step42 的固件有可抄价值，而且价值集中在一处： 它把「视觉只喂一个误差标量、驱动器自己跑 1 kHz 闭环、输出速度而不是位置增量」这套架构完整实现了， 并配了一整套围绕该架构的工程细节（预测补偿、连续增益、最小动作量、输入超时停机、遥测流）。 滑环仓库是纯机械件（3D 打印外壳 + 转接 PCB + BOM）， 没有软件可抄，只在"将来真要走滑环过线"时作为机械参考 + 电气风险清单有用。

最关键的一条

我们现在的闭环是「每帧发一次相对脉冲增量」，被 COMMAND_INTERVAL_S=0.08 限到 ≤12.5 Hz， 本质是一个低带宽位置环；步进电机每帧「起步—停」一次，方向每翻一次就要重吃一遍回差（≈9.7 px）。 Step42 的做法是「PID → 速度指令 → 驱动器连续走」，方向不变就不停， 且带 I 项后稳态误差与 PULSE_PER_PX 标定精度脱钩 —— 这正好绕开我们登记在案的「3.67 是占位值」风险。

02Step42 值得学的五个设计

① 内外环分层：视觉 60 fps 喂误差，驱动器 1 kHz 跑环

它的 TRACK_PID 模式专门为"视觉模块"设计。视觉端只需发一行 ASCII 十进制整数（换行结束）， 不带 CRC、不带 ACK，40 Hz~60 Hz 都够用；驱动器在 1 kHz 节拍上继续跑 PID， 帧间自己外推，并在输入超时（默认 250 ms）后自动停机。

-123\n          ← 视觉端唯一要发的东西（范围 -10000 ~ +10000）

关键取舍：高频通道（视觉误差）与低频通道（控制指令）分离。 换行作帧边界意味着丢字节永远不会让解析器永久错位 —— 二进制帧一旦错位可能长期失步。

UART_PROTOCOL.md §"Visual Error Fast Path"；Step42Comms.c Ctrl_ParseVisionError() / Ctrl_ProcessVisionErrorByte()

② 误差低通 + 导数外推，而不是"用原始值换低滞后"

它不靠降低滤波强度来换相位，而是先低通保留抑噪，再用滤波误差的导数把误差超前外推 prediction_ms 毫秒：

filtered  += alpha * (raw - filtered);          // alpha 默认 0.25
derivative = (filtered - prev_filtered) / dt;
predicted  = filtered + derivative * prediction_ms * 0.001;

Step42Tracking.c Step42Tracking_Update()，第 241–254 行

直接命中我们的痛点

我们因为「CENTER_ALPHA=0.70 附加 ≈28 ms 滞后、底盘运动时直接变瞄准误差」， 只好把闭环口径切成 AIM_USE_RAW=True —— 用"完全不滤"换相位，代价是噪声全进闭环。 这个外推项让两个目标可以同时拿到，而且几乎不增加算力（每帧两次减法 + 一次乘加）。

③ 连续增益调度，而不是二段硬切换

gain = gain_min + (gain_max - gain_min) * clamp(|predicted| / full_error, 0, 1)

误差越大增益越高，按误差幅值线性插值。full_error 是"满增益误差"。 好处很实际：在切换点附近不会产生指令突变（我们不连续，|e| 跨过 24 px 时增益从 0.5 跳到 0.9）， 对云台这种有惯性的负载，突变就是一次可听可见的抖动。

Step42Tracking.c 第 255–257 行，参数经 0x12 TRACK_ADVANCED 下发

④ "决定要动，就至少动这么多"——最小修正速度

#define WEAK_PID_MIN_CORRECTION_SPEED (80.0f)   // steps/s
if ((output > 0) && (output < 80.0f))  output = 80.0f;
if (AbsF(output) < 1.0f) { Stepper_Stop(...); return; }

逻辑是分段的：小于 1 steps/s → 干脆停；在 1~80 之间 → 抬到 80。它拒绝"以极低速爬行"这个区间， 因为静摩擦 + 回差会让爬行变成"抖而不动"。这一条对我们尤其对味：我们的闭环有 MAX_STEP_PULSES=360 上限，却没有下限，理论上可以发出 1 脉冲的指令 —— 那连回差都咬不穿。

Step42Control.c WeakPID_Update() 第 933–971 行

⑤ 换向清停 + 斜率限制 + 超时停机，三件事缺一不可

  • 换向清停：速度模式下一旦目标速度与当前速度符号相反，先 Stepper_Stop() 再反向重启， 不做"直接翻转"（步进电机直接反相会丢步）。
  • 斜率限制：支持梯形与 S 曲线两档，S 曲线用 jerk = accel / 30 ms 限加加速度， 并在脉冲级（TIM1 中断里）逐脉冲更新 ARR，规划器与 PID 的职责严格分离 （TIM6 里的 PID 只写 target_speed，永不写 TIM1 的时序寄存器）。
  • 超时停机：timeout_ms（默认 250 ms）内没收到新的误差 → 停。

Stepper.c Stepper_UpdateSCurveAtPulse() / Stepper_Set_Speed_Profile()；Step42Tracking.c 第 234 行

04借鉴清单（按"该不该现在做"分三档）

A 档 立刻可抄 · 低风险 · 不改架构 预计只动 2~3 个文件 + 加若干 config 项
#改什么落地位置为什么值
A1 误差导数外推（借鉴 prediction_ms） config.py 新增 PREDICT_MS；gimbal_aim 或 laser_spot.deviation 后加一级一阶低通 + 外推 补掉 CENTER_ALPHA=0.70 的 ≈28 ms 滞后，同时把噪声滤掉 —— 不再是"滤噪 vs 相位"二选一
A2 二段增益 → 连续增益 config.py 加 GAIN_FULL_PX；改写 gimbal_aim._gain() 消除 |e|=24px 处 0.5↔0.9 的指令突变；代码量约 5 行
A3 最小动作量（借鉴 80 steps/s 那条） config.py 加 MIN_STEP_PULSES；gimbal_aim._axis_command() 的 max(1, …) 改成 max(MIN_STEP_PULSES, …) 直接缓解"回差 1°≈9.7px 吃掉整个预算"：要么不动，要么一步咬穿回差
A4 失锁后主动停机 config.py 加 LOST_STOP_FRAMES；gimbal_aim._on_lost() 在 HOLD 累计到阈值时返回一个 stop 动作，由 AimLoop 调 link.stop() 现在 HOLD 只是不发指令。若将来改成速度模式，不发指令 = 一直按上次速度走， 这是安全事故。即便保持位置模式，"主动停"也更明确
A5 ACK 看门狗加 SEQ/命令回显匹配 stepper_link._ingest()：记录最近发出的命令，比对返回帧功能码 现在只判"有没有收到确认帧"，不判"回的是不是我刚发的那条"。多轴/混合命令时可能误判健康
A6 遥测流（借鉴 0x06 Stream） main.py：新增 TELEMETRY_INTERVAL_S，周期打印 yaw: e/out/rpm/ok/e2 结构化的单行 CSV PC 侧可以直接喂进脚本画波形调参；现在 2 s 一行日志基本没法调 PID
B 档 值得做的架构改造 · 中等风险 · 收益最大 建议先在 PC 仿真里跑通再上板
B1 · 首推

把"每帧相对脉冲增量"改成"速度指令"闭环。 好消息是管道已经铺好了：vision/stepper_link.py 里 cmd_speed()（ZDT 0xF6）和 link.speed() 都已实现并有单测 （tools/test_gimbal_aim.py 第 84 行逐字节校验），只是闭环路径没调用它。

收益：

  • 方向不变就不停，回差只在真正换向时吃一次（现在是每帧都吃）；
  • 加上 I 项后稳态误差与 PULSE_PER_PX 精度解耦 —— 直接绕开"3.67 是占位值、标定错就正反馈"的风险；
  • 12.5 Hz 的更新率不再是硬瓶颈：速度指令的低频更新只影响加速快慢，不影响稳态指向。

必须同时补上的三件事（缺一个就会出问题）：斜率限制（限制相邻两帧速度指令的变化量）、 换向清停（借用 Step42 的 stop → 反向 restart）、 超时停机（A4）。ZDT 速度模式的 acc 参数与我们现在的 "增量闭环必须 acc=0"经验不冲突 —— 那是位置模式的约束。

B2 · 可选，需评估

把内环下放到 MSPM0G3507。 Step42 之所以稳，根子在于"环在电机旁边、跑 1 kHz"。我们没有这样的驱动器能力（ZDT 不支持外部误差输入）， 但我们有一条现成的 MaixCAM2 ↔ 3507 的 SPI 链路。 理论上可以让 3507 跑 200 Hz~1 kHz 的位置/速度环，MaixCAM2 只经 SPI 喂 dx/dy， 这样视觉帧率抖动不会直接进入控制环。

代价：多一跳延迟（SPI + 3507 调度）、3507 要占引脚和算力、调试面扩大一倍。 建议：先做 B1；只有当实测发现"12.5 Hz 外环带宽真的不够"时，再考虑 B2。 不要为了架构漂亮而先做 B2。

B3 · 可选

串级控制：外环视觉误差 → 内环陀螺角速度。 Step42 的 TRACK_CASCADE 模式就是"outer（慢，视觉误差）+ inner（快，陀螺/速率反馈）"。 我们 main.py 已经有 probe_imu() 探测到 IMU （日志 [imu] sample via …）。若打算做"底盘运动时瞄准"，陀螺进内环比在视觉误差上做外推（A1）更本质 —— 视觉误差里混了底盘运动和真实瞄准误差，陀螺能干净地分离出前者。

C 档 备查 · 现在不做，但记一笔
  • 自研驱动板选型：STM32G431 + TMC2209 + MT6701（14 bit，SPI，帧带 CRC-6 x⁶+x+1） —— 若将来要脱离 ZDT 做定制板，这套 BOM 与 SDK/step42_protocol.c 可直接抄。
  • CAN 传输：同一套帧拆成 8 字节 CAN 包（A0 起始 / B1..BF 续帧）， ID 0x300+node / 0x340+node，30 ms 内顺序到达，端到端 CRC 不变。 若将来云台总线化（多轴 + 3507 共线），这是现成模板。
  • Flash 配置持久化：magic + version + CRC 结构体 + 保留旧版布局以便兼容读取。 我们的标定结果目前靠"打印 → 人工回填 config.py"，可参考这个做法落盘。
  • 调试口权限隔离：Step42 在 CAN 模式下把 Debug UART 限制为"只能 Query/遥测/调 PID"， 禁止发运动指令。我们可以照做：MaixVision/串口调试只读，运动指令只走电机串口。
  • 状态码集合：OK / BAD_LEN / RANGE / UNKNOWN_CMD / BAD_MODE / BUSY / DENIED —— 比"成功/失败"两态更能定位问题。

05滑环仓库：能给什么、不能给什么

它能给的它给不了的
  • 42mm 滑环的机械封装：三件 3D 打印外壳（顶板/底板/整壳）STL
  • 顶/底板转接 PCB（立创EDA 专业版工程，含导入说明）
  • 装配 BOM：6P 2.0mm 弹片触点 ×2~4、M3 铜柱螺丝、杜邦线
  • 作者 B 站 UID（源视频出处）
  • 滑环本体规格全无：通路数、额定电流/电压、转速、接触电阻、寿命
  • 没有任何软件（无固件、无驱动、无协议）
  • 没有走线方案说明（哪几路进滑环、几根线、屏蔽怎么做）

结论：纯机械参考件。软件层面零可借鉴。

如果将来真要走滑环过线 —— 四条电气提醒

与我们的现状直接相关
  1. UART 穿滑环会引入接触噪声与瞬时断路。这恰好印证了 B 轨已经做的 ACK 硬超时 + E2 洪水看门狗是对的方向；若板端实测误码变多， 建议降波特率（115200 → 57600 甚至 38400）并补 CRC + 重传，而不是加大重试次数硬扛。
  2. 电机相电流不要过滑环。斩波噪声会串进信号线；且滑环接触电阻波动会让驱动器供电跌落， 被误判为 0xE2（未使能/堵转）甚至复位 —— 而我们现在的策略是 E2 洪水直接 FAULT 停机， 会产生"莫名其妙就停了"的假故障。
  3. 电源与信号走不同环道，信号线尽量双绞 + 就近接地，弹片触点选镀金。
  4. 若云台需连续 360° 旋转（而不是现在的往复摆动），滑环才有必要； 否则线束的"软限位 + 累计脉冲上限"（我们已有 SCAN_LIMIT_PULSES 这类思路）更便宜可靠。

06明确不建议跟的地方

Step42 的做法为什么我们不跟
把 PID 放进驱动器，视觉只喂一个标量误差 ZDT Emm_V5.0 不支持外部误差输入，这条路在我们的硬件上不存在。 能借的是"输出速度而非位置增量"这个结果（即 B1），不是它的实现方式。
ASCII 纯文本误差通道（无 CRC、无 ACK） 我们能直接拿到 dx/dy 两个分量，二进制帧更省带宽也更精确。 它的 ASCII 通道是为了"让任何视觉模块都能 5 分钟接上"，我们没有这个兼容性需求。 唯一值得记的是设计思想：高频数据通道和低频控制通道分开。
program 程序化运动（8 步、可存 Flash、KEY1 长按离线运行） 我们的任务是实时瞄准，不是跑示教程序。复杂度远大于收益。
整块移植 Step42Control.c（61 KB） 它是"驱动器固件"，我们的 gimbal_aim.py 只有 178 行、是"外环控制器"。 移植会产生大量无用抽象。只抄算法片段（Step42Tracking.c 300 行不到）。

07建议的落地顺序

第 1 步 · 只改控制律，不动链路（A1 + A2 + A3）

在 gimbal_aim.py 里加"低通 + 外推"、把二段增益换成连续插值、加最小动作量下限。 三个都可以在 PC 上用现成的 tools/test_gimbal_aim.py 离线回归（该测试已有闭环收敛用例）。

第 2 步 · 补安全项（A4 + A5）

失锁主动停机 + ACK 带命令回显匹配。这两条是 B1 的前置条件 —— 没有它们就切速度模式是危险的。

第 3 步 · 加遥测流（A6）

先把"看得见"做好。切速度模式后如果没有结构化遥测，调参基本靠猜。

第 4 步 · 上板标定，拿到真实回差与 PULSE_PER_PX

跑现有的 CALIBRATE_AXIS="yaw"/"pitch" 各一次。这一步是 B1 能不能成的判据来源： 实测回差有多大，直接决定 MIN_STEP_PULSES 和死区该取多少。

第 5 步 · 切速度模式闭环（B1）

写一个 SpeedAim 变体（复用 GimbalAim 状态机 + link.speed()）， 与现有位置增量闭环同进程 A/B 对照（沿用本项目"性能结论必须交错对比"的铁律）。 实测确实更好再切默认。

第 6 步 · 视结果决定是否做 B2 / B3

只有当实测证明 12.5 Hz 外环带宽真不够、或底盘运动时瞄准误差压不下来，才考虑 3507 内环（B2）或陀螺串级（B3）。
