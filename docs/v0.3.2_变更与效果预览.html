2026-10-11 增补：板端 2fps 定案修复（慢图传不再拖死主循环）

板端日志给出决定性证据：[perf] ... read=5.8 detect=10.7 ... show=509.1 loop=526.2 ms —— 识别只要 10.7ms，而 MaixVision 图传单帧 show 阻塞 509ms。同步预览旧节拍 _next = now + max(0, _period − show_s) 在 show_s ≥ _period（509ms ≥ 500ms）时恒为 0 → 每个循环都 show → 主循环被钉在 ≈1.9fps，追踪控制率也塌到 2Hz，V9 手感参数被完全埋没。
指标修复前修复后
MaixVision 单帧 show≈509ms≈509ms（链路固有，不变）
主循环 loop（即追踪控制率）≈1.9fps≈30fps（间隙全速跑）
预览显示帧率≈2fps≈1fps（代价）

改法：idle = max(_period − show_s, show_s × SHOW_MIN_IDLE_RATIO) —— show 之后至少留 ratio×show_s 的空闲（新增 Config.SHOW_MIN_IDLE_RATIO，默认 1.0）。 快图传完全不受影响。回归用例 test_sync_preview_keeps_loop_alive_when_show_longer_than_period 实测 ticks=92 / shows=2（旧实现 ticks≈shows）。

取舍：SHOW_MIN_IDLE_RATIO 越大越保主循环、预览越卡；越小反之。 不需要预览就直接 SHOW=False（主循环≈60fps，最彻底）。SHOW_ASYNC=True 已被 v18 证伪，勿用。

⚠ 风险与回调旋钮

主要风险：超调 / 过冲。 当初把 GAIN 0.5→0.3、关滤波、加限速，正是因为现场反馈"旋转角度过大、超调"。 本版把它们整体调回，跟手度上升、稳定性下降。上电前务必先架空云台试跑。
若出现回调做法
大误差时冲过头GAIN_COARSE 0.9 → 0.7（或 0.5）
停下瞬间激光晃动AIM_OUTPUT_SLEW_PPS 0 → 400（重新开启增长限速）
持续抖 / 不收敛GAIN_YAW/PITCH 0.5 → 0.35；或 DEADBAND_PX 调大
