# 云台控制说明

云台部分在整条链路里的位置：**视觉给出像素误差，云台把它变成两台步进电机的动作**。
它的职能只有两件——把可信测量变成动作；在拿不到可信测量时让电机停下。
识别侧见 `maixcam2_rect_center/README.md`；参数数值一律以 `config.py` 为准，这里只给符号名。

## 1. 职责与边界

**负责**

- 建立两条独立的 UART 链路，编码并下发 ZDT 驱动器指令；
- 由"靶心 − 光斑"的像素偏差生成**单帧增量**位置指令（相对位置，不维护绝对坐标）；
- 状态机（`BOOT / COARSE / FINE / SETTLE / HOLD / FAULT`）、死区、限频、单帧限幅、
  离群拒收、发散看护；
- 处理驱动器返回帧（ACK / E2），据此判定链路是否健康，异常时停机。

**不负责**（刻意没有编入，别在这里找）

- 失锁后的搜索扫描——识别层只做"回到全图重捕获"，云台不主动扫；
- `PULSE_PER_PX_*` / `DIR_SIGN_*` 的自动标定——需要人工开环标定后填回配置；
- 回零、机械限位、IMU 前馈、屏幕按钮与手动点动。

这条边界决定了一个重要性质：**云台只对"当前这一帧的测量"负责**。
没有测量就不动，宁可停着也不外推着走。

## 2. 硬件拓扑与轴映射

| 代码里的轴 | 串口 | 丝印 | 引脚 | 设备路径 | 驱动器 ID | 正方向 |
|---|---|---|---|---|---|---|
| **pitch**（俯仰） | UART0 | `U0T` / `U0R` | A28 / A29 | `/dev/ttyS0` | **1** | CCW = 上 |
| **yaw**（偏航） | UART2 | `U2T` / `U2R` | B0 / B1 | `/dev/ttyS2` | **2** | CCW = 左 |

两条定案规则：

1. **ID 跟着电机走，不跟端口。** 换线、换口都不改 ID；地址对不上表现为"该轴完全不动"。
2. **两轴都必须显式 pinmap。** U0 走空表会静默不通（引脚停在默认功能，TX 根本没接到 UART）；
   因此 `PITCH_PINS` / `YAW_PINS` 不是可选优化，是接线的一部分。
   `PINMAP_STRICT=False` 时 pinmap 失败只告警、仍尝试打开串口——避免把真故障藏成"打不开"。

U0 同时是**系统日志口**：开机阶段内核日志、终端回显会混进 RX，所以
`FLUSH_RX_ON_START` 在链路建立后先丢弃残留字节，再开始解析返回帧。

两轴链路互相独立：任一轴打开失败只把该轴标记为不可用，另一轴照常发令。

## 3. 控制协议

驱动器为 ZDT Emm42_V5.0（闭环步进），通讯协议见 `ZDT电机资料/` 的手册页索引。

### 3.1 帧格式

```
| addr | func | data ... | 0x6B |
```

| 字段 | 含义 |
|---|---|
| `addr` | 驱动器 ID（1 字节） |
| `func` | 功能码 |
| `data` | 定长参数，**大端** |
| `0x6B` | 固定校验字节 |

校验方式由驱动器菜单的 `Checksum` 决定，必须设为 `0x6B`；换成 XOR/CRC-8 后本链路所有帧都会失效。
本项目不使用 0xFF 同步广播，所有命令都是**单机模式**（同步标志位为 0）。

### 3.2 四条命令

| 功能码 | 用途 | 数据字段 | 何时发 |
|---|---|---|---|
| `F3` | 使能 / 失能 | `AB` + 使能位 + 同步位 | 上电一次；收到 E2 时按轴补发 |
| `FD` | **位置控制（相对）** | 方向 + 转速(2B) + 加减速档 + 脉冲数(4B) + 绝对/相对位 + 同步位 | 闭环**唯一**的运动命令 |
| `FE` | 立即停止 | `98` + 同步位 | 失锁、过期、停机、故障兜底 |
| `F6` | 速度控制 | 方向 + 转速(2B) + 加减速档 + 同步位 | 链路具备，闭环不用 |

`FD` 的关键点在**绝对/相对位 = 相对**：每帧只发"这一帧该补多少脉冲"，不写绝对目标。
好处是一帧丢失只少走一段，下一帧按新测得的误差继续补，不会累积成位置漂移；
代价是必须每帧都有新测量，所以"没有测量就不发"是硬规则。

参数边界：转速夹到驱动器量程，脉冲数取绝对值（方向单独一位），加减速档 `0` 表示不用曲线加减速
（值越小加减速越柔，`0` 等于瞬时启停，工程上不要用）。

### 3.3 返回帧与状态码

```
| addr | func | status | 0x6B |
```

| `status` | 含义 | 处理 |
|---|---|---|
| `0x02` | 命令被接受 / 已到位 | 计成功，刷新该轴 ACK 时刻 |
| `0xE2` | 未使能、堵转一类拒绝 | 计一次 E2；`E2_REENABLE` 打开时按轴补发 `F3` |

返回帧只在驱动器菜单 `Response` 设为 `Receive` / `Reached` / `Both` 时才出现。
设为 `None` 时该轴永远不回帧——链路仍能发令，但**无法确认到位**，ACK 看门狗对该轴自动停用
（见 §7），只打一次告警。

## 4. 数据流与三条硬时序

```
采图 ──► 识别（靶心 u,v）──► deviation：dx = u靶心 − u光斑
                                        │
                                        ▼
                              GimbalAim.update(dx,dy) ──► cmds{yaw,pitch}
                                        │                   (ccw, pulses, rpm)
                                        ▼
                              VisionControl ──► apply_commands ──► UART ──► 驱动器
```

三条不可改的时序约定：

1. **同一次测量**：`dx/dy` 与 `captured_at` 必须来自同一帧。闭环取未平滑的 `raw_u/raw_v`，
   避免平滑带来的相位滞后被当成"目标还没到"。
2. **过期即废**：以采图时刻计龄超过 `RESULT_MAX_AGE_S` 的结果整体判废（`stage=stale`），
   **不画框、不下发**，并停机一次。旧误差绝不允许驱动电机。
3. **先停后走**：每轮先处理 `stops`，再下发 `cmds`；`stop_motion()` 返回失败必须**立即终止**
   本轮决策链，不能继续下发。`apply_commands` 任一轴失败即停机并把整机置 FAULT。

## 5. 闭环控制律

单轴换算链：

```
脉冲 = |e| × PULSE_PER_PX_轴 × GAIN_轴     （再受 MAX_STEP_PULSES 单帧限幅）
方向 = sign(e) × DIR_SIGN_轴
```

**增益混合**：`GAIN_轴` 不是常数，而是按 `|e|` 在 `GAIN_*`（细调）与 `GAIN_COARSE`（粗调）之间
线性过渡，分界点是 `COARSE_PX`；转速同样在 `RPM_FINE` 与 `RPM_COARSE` 之间过渡。
`AIM_PROGRESSIVE` 关闭时退化成二段式（超过 `COARSE_PX` 直接用粗调）。
两个增益都必须 **≤ 1**——这是增量式闭环，增益大于 1 会一帧比一帧过冲。

**为什么是增量而非绝对**：视觉每帧给的是"当前还差多少"，绝对定位需要知道云台当前的真实角度，
而本项目没有编码器读数回传（`Response=None` 时连到位都无法确认）。增量式把"我走到哪了"
这个问题彻底绕开，代价是必须每帧重新测量。

其余五道闸门：

| 机制 | 作用 | 配置项 |
|---|---|---|
| 死区 | `|e|` 在此范围内不发令，避免在齿隙里来回抖 | `DEADBAND_PX` |
| 指令限频 | 两条指令的最小间隔，防指令堆叠"冲过头" | `COMMAND_INTERVAL_S` |
| 单帧限幅 | 一帧最多发多少脉冲，防目标跳变甩头 | `MAX_STEP_PULSES` |
| 等待运动 | 按驱动器梯形速度模型估算本段运动时间，未走完不发下一条 | `AIM_WAIT_MOTION` / `AIM_MOTION_MARGIN_S` |
| 离群拒收 | 单帧误差超过门限先当误检丢掉，连续若干帧才采信 | `JUMP_REJECT_PX` / `JUMP_CONFIRM_FRAMES` |
| 发散看护 | 误差持续**同号变大**到一定次数即判发散，直接 FAULT 停机 | `DIVERGE_GUARD` / `DIVERGE_RATIO` / `DIVERGE_MIN_PX` / `DIVERGE_CONFIRM_FRAMES` |

发散看护是最后一道保险：方向接反或增益过大时，闭环会越追越偏。它不会"自动纠正"，
只会**停下来并锁死**，把问题暴露给人——这比带着错误方向一路撞到机械限位要好。

## 6. 状态机

| 状态 | 触发 | 行为 |
|---|---|---|
| `BOOT` | 上电初始 | 等第一帧有效测量 |
| `COARSE` | `max(|dx|,|dy|) > COARSE_PX` | 用粗调增益/转速，大步逼近 |
| `FINE` | 偏差在死区与 `COARSE_PX` 之间 | 细调增益，小步收敛 |
| `SETTLE` | 两轴都进入死区 | 不发令，保持 |
| `HOLD` | 本帧无有效测量（无框 / 光斑丢失 / 结果过期） | 停机一次，之后保持静止 |
| `FAULT` | 链路故障、发散、下发失败、使能失败 | **不再发任何指令**，需重启恢复 |

`FAULT` 是终态，没有自动复位。这是刻意设计：任何"自动重试"都可能带着错误状态继续驱动电机。
`GIMBAL_CALIBRATED=False` 时云台整体只做识别、不发令（标定前的安全模式）。

上电时序：双轴使能 → 建显示 → 进主循环。**上电不发脉冲**，云台不会自己动。

## 7. 链路健康

- **ACK 看门狗按轴独立武装**：只有当某轴**自己回过帧**（`Response` 已配置）时，才要求它继续回帧；
  从未回过帧的轴只告警一次、不据此判障。否则一轴正常、另一轴 `Response=None` 会把整机拖进 FAULT。
- **E2 自动补使能**：收到 E2 说明驱动器未使能或堵转，按轴补发一次 `F3`。
- **E2 洪水**：窗口内 E2 次数超限即判链路故障（堵转卡死、供电塌陷一类），进 FAULT。
- **RX 超时**：只在收到过确认帧之后生效；连续超时超过上限判故障。
- **单轴降级**：一轴打不开不影响另一轴发令；但任一轴触发 FAULT 后整机停止决策。

## 8. 可实现的效果

在 `PULSE_PER_PX_*` 与 `DIR_SIGN_*` 完成实机标定的前提下，本云台部分能做到：

1. **把激光点推向靶心**：连续帧增量修正，偏差单调收敛到死区内（`SETTLE`）。
2. **大偏差快速接近、小偏差轻柔收尾**：增益与转速随 `|e|` 过渡，不会在远处磨蹭或在近处过冲。
3. **目标跳变不甩头**：单帧限幅 + 离群拒收，误检一帧最多让云台走一小步。
4. **目标丢失即停**：无框、光斑丢失、结果过期一律停机，不会"照着旧位置一直追"。
5. **异常自动止损**：无 ACK、E2 洪水、方向接反导致的发散，都会停机并进 FAULT。
6. **标定前可只跑识别**：`GIMBAL_CALIBRATED=False` 时画面照常出结果，电机不动。

做不到的（属于识别侧或机械侧）：失锁后自动搜索、命中后的二次精调（没有闭环末端反馈）、
大幅度的绝对角度定位。

## 9. 注意事项

**接线与驱动器**

- 两轴 pinmap 必须显式配置；U0 空表静默不通，这是"yaw 不动"的历史根因之一。
- 驱动器菜单三项必须改：`P_Serial → UART_FUN`（出厂 `RxTx_OFF`，不改则串口完全不响应）、
  `UartBaud` / `Checksum` / `Response` 与配置一致、`ID_Addr` 两轴分别为 1 / 2。
- 共地必须接；TTL 串口只接 TX/RX/GND。

**标定**

- `PULSE_PER_PX_*` 是主参数，未标定前是占位值，闭环只能"动"不能"准"。
- `DIR_SIGN_*` 按几何推断、未标定。**上电追踪若越追越偏（误差持续变大、云台一路跑向一侧），
  把对应轴翻号**；发散看护会兜底停机，不会撞到底。
- 改完手感一次只动一个数，跑一轮再动下一个——一次改多个分不清谁起作用。

**运行**

- 上电不发脉冲；要单独验证电机动作，用 `target_api.AimLoop` 跑，不要临时改主循环。
- 串口归识别线程独占。**禁用 `pkill` / `kill` 停程序**（会留下占用的串口），只走 MaixVision 停止按钮。
- 程序退出走"先停电机、再关串口"的顺序；线程没退干净就动 UART 会打架。
- FAULT 只能重启恢复。进 FAULT 后先看 `[aim] FAULT: <reason>` 的原因码再决定改什么。

**参数语义**

- 六个增益/转速/限幅值会被 `apply_aim_profile(AIM_PROFILE)` 在配置加载时**覆盖**，
  直接改字面值可能不生效；改这六项要动 profiles 表或换档位名。
- 死区应不小于实测回差的 1.5 倍，否则会在齿隙里持续抖动。

## 10. 日志与排障入口

| 日志 | 看什么 |
|---|---|
| `[gimbal] pinmap ... ok (readback=...)` | 引脚实际功能回读，判断"某轴不通"的第一手证据 |
| `[gimbal] WARN ... 从未返回确认帧` | 该轴 `Response` 未开，链路能发不能确认 |
| `[aim] state=... dx=... yaw=CCW/120p` | 当前状态、闭环误差、实际下发的方向与脉冲 |
| `[aim] FAULT: <reason>` | `diverge:yaw` / `ack_timeout:pitch` / `e2_flood(...)` / `tx:yaw` / `enable_failed` |
| `[perf] ... age=...ms` | 结果新鲜度；age 持续接近 `RESULT_MAX_AGE_S` 说明识别拖慢了闭环 |

按现象定位：

| 现象 | 先查 |
|---|---|
| 两轴都不动 | `ENABLE_GIMBAL`、`[gimbal]` 是否有 open failed、是否已 FAULT |
| 单轴不动 | 该轴 pinmap readback、`ID_Addr`、`P_Serial` 是否为 `UART_FUN` |
| 动了但越追越偏 | `DIR_SIGN_*` 翻号；再看 `PULSE_PER_PX_*` 是否过大 |
| 到位后来回抖 | `DEADBAND_PX` 小于机械回差，或增益过大 |
| 冲过头再回摆 | 降 `GAIN_*` / `MAX_STEP_PULSES`，或加大 `COMMAND_INTERVAL_S` |
| 频繁进 FAULT | 看原因码：`ack_timeout` 查 `Response`；`e2_flood` 查供电/堵转；`diverge` 查方向 |
