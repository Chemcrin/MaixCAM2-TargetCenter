# 视觉识别实现说明

本文记录识别链路的**流水线分层、数据结构、参数作用与已知边界**，用于两件事：
现场分阶段调参，回滚时确认边界。

- 系统整体结构与云台链路 → 应用目录 `README.md`
- 参数当前取值 → `config.py`（本文只给符号名）
- 哪一轮改了什么 → git 历史（本文不记流水）

## 1. 范围

识别链路只剩三个文件：

```
camera_source.py     MaixPy 帧 → uint8 灰度 ndarray
rectangle_center.py  二值化 → 轮廓 → 四层过滤 → 择优 → 四边精修 → 对角线交点 → 绘制
aim_control.py       消费 u/v，算偏差、下发串口、驱动闭环
```

`target_api.py` 是这层的对外门面，`vision_worker.py` 负责线程调度，二者不含识别逻辑。

`tools/test_rectangle_detect.py` 是这一层唯一的回归门禁：合成靶纸测中心精度与旋转/竖放，
真实帧测"还能不能检出"，负样本测不误锁。

**已删除**（旧判据，不要试图恢复其中的片段）：`contour_locator.py`、`rect_geometry.py`、
`kalman_filter.py`。它们对应的 Canny/Otsu 提案、四边暗带验证、亚像素迭代精修、单应反算、
匀速卡尔曼与运动预测一并移除。需要更强鲁棒性时**新增一层判据**，不要回退到旧结构。

## 2. 流水线

组织原则：**每个小功能都是模块级函数**，只依赖入参、不读类状态；`RectangleCenterDetector`
只保存参数、维护跨帧先验并按顺序调用它们。任何一步都能单独跑、单独测，
`diagnose_detect.py` 就是直接调 `blur_frame` / `binarize_frame` / `find_quad_candidates`。

| 步 | 入口 | 输入 → 输出 | 参数 |
|---|---|---|---|
| 1 灰度 | `to_gray_frame` | 帧 → `(H,W)` uint8（去哑轴、校验类型） | 无 |
| 2 模糊 | `blur_frame` | 灰度 → 灰度 | `RECT_GAUSS_KERNEL`，置 `(0,0)` 跳过 |
| 3 二值化 | `binarize_frame` | 灰度 → 二值图 | `RECT_BLOCK_SIZE`、`RECT_C` |
| 4a 候选 | `find_quad_candidates` | 二值图 → 候选列表 + 淘汰计数 | `RECT_MIN_AREA`、`RECT_MAX_AREA_RATIO`、`RECT_APPROX_EPS`、`RECT_MIN/MAX_ASPECT` |
| 4b 胶带证据 | `filter_band` | 候选 → 过证候选 | `RECT_MIN_BAND_SCORE`、`RECT_MIN_BAND_RATIO`、`RECT_BAND_MIN_UNIFORM`、`RECT_MIN_INNER_MEAN`、`RECT_MIN_EDGE_SCORE` |
| 5 择优 | `select_best` | 候选 → 一个 | `RECT_PRIOR_FRAMES`、`RECT_PRIOR_RADIUS_PX` |
| 6 精修 | `refine_quad` | 候选 + 轮廓 → 亚像素四角 | `RECT_EDGE_*` |
| 7 中心 | `success_result` / `quad_diagonal_center` | 四角 → 交点 | 无 |

锁定之后走另一条路（`refine_edges_1d`）：以上一帧的四边为基准，沿各边法向做一维灰度搜索，
找"由亮转暗"的跳变位置，重新拟合直线求交。它比全图重搜便宜一个数量级，而且每条边由
十几个跳变点共同决定，顶点天然连续——这是"四个端点不再逐帧跳动"的主要来源。
连续跟踪达到 `RECT_TRACK_MAX_FRAMES` 会强制回一次全图，阻止误差累积。

**第 3 步是整个链路的地基**。`adaptiveThreshold` 用局部均值做参考、`THRESH_BINARY_INV`
反色，黑胶带因此变成白色环带，白纸与亮背景变黑。窗口的绝对值很关键：它必须**大于胶带的
像素宽度**，否则胶带中心也被算作"和周围一样暗"，白环会被挖空成两条细线，
后面的近似就再也凑不出四条边。现场距离变化会让胶带宽度成倍变化，这是这一层最先要核对的量。

**第 4a 步取轮廓时连同内孔一起遍历**（`RETR_CCOMP`）。黑框与桌面、窗框这类暗结构相连时，
最外层轮廓会被整块吞掉；而黑框围出的纸面是独立的内孔，不受连通影响。实拍里"明明看得见
却检不出"绝大多数是这一条。形状有两条路：多边形近似正好四点就用它（透视四边形，最准）；
近似不出四点时退一步用最小外接矩形，配 `area / rectArea` 的填充度下限——胶带环有一处
缺口、纸面漏气时轮廓不再是闭合四边形，但外接矩形仍贴着纸边。

**第 4a 步的长宽比用四边形自身的对边长度比**，不用正立外接框。外接框在旋转时趋近正方形、
竖放时落到 1/1.414，这两种现场都会出现；对边比与朝向无关，同一张 A4 始终落在 1.414 附近。

**第 4b 步是胶带证据，四项缺一不可**：

1. `band_score`：边界内侧亮、外侧暗的采样点占比。它证明"这条边外面确实有一圈更暗的东西"。
2. `min_edge_score`：要求**至少三条边**同时成立——靶纸四周都有胶带，而屏幕里的一块深色
   窗口往往只有两三条边侧面恰好更暗。允许一条边缺失，是为了容忍手和画面边缘。
3. `band_thickness`：暗带厚度占边长的比例。18mm 胶带贴在 210mm 宽的纸上约 8%，而显示器
   边框、窗框、桌沿通常只有 1%~2%。**暗带的边界用灰度回升界定，不用任何绝对灰度阈值**：
   沿外法向取剖面、找最暗处、再往外找第一次显著回升（`RECT_BAND_RISE_STEP`），回升点就是
   胶带外沿。这样量到的是"纸边到胶带外沿"的物理宽度，与整幅画面的曝光无关。
   早先用过"灰度低于某个绝对值才算胶带"，画面一亮胶带灰度就越线，四条边同时量不出厚度，
   整帧判负——这类阈值不能再引入。
4. `band_uniform` + `inner_mean`：四边同宽（同一卷胶带，只有三条边以上有效才判），
   且框内足够亮（是白纸不是暗面板）。框内亮度按**全图均值的比例**给门限
   （`RECT_MIN_INNER_RATIO`），不按绝对灰度——现场偏暗时整幅一起暗，固定灰度会把正常靶纸判死。

**第 5 步**在没有先验时取面积最大者；有先验时先在半径内挑"距离平方除以面积"最小的那个，
圈内一个都没有才退回面积最大。先验由丢失帧数决定是否给——丢失超过 `RECT_PRIOR_FRAMES`
就彻底放弃，避免被旧位置困死。

**第 6 步**把每条边附近的轮廓点做最小二乘拟合、再求相邻直线交点。任何一条边凑不够点、
或精修位移超过 `RECT_EDGE_MAX_SHIFT_PX`，就原样返回输入四边形：宁可给粗角点，
也不要给跑偏的角点。

## 3. 为什么中心用对角线交点

正立外接框的中心在目标旋转时会偏：框本身随旋转变大，中心也随之漂移。
四个顶点本来就已经由近似得到，交点计算是几次乘除，成本可忽略，而且**透视下无偏**。

合成靶纸实测（白底 + 黑环 + 光照梯度 + 噪声，同一目标旋转三个角度）：
不旋转时中心与真值完全重合，旋转十几度与二十几度时仍在亚像素级。同期外接框中心
已经出现可见偏移。这条结论是选择交点的唯一理由，不必再引入单应与物理尺寸。

## 4. 已知边界

这些是方案的**原理性边界**，不是参数没调好，调参解决不了：

1. **纸面缺口过大时整帧判负**。遮挡把胶带环打断、或纸面与外部暗区连通时，内孔不再是闭合
   四边形；最小外接矩形只能在缺口不大时兜住。这类帧靠跟踪跨过去，不靠放宽判据。
2. **画面里存在同类物体会抢锁**。"白亮面 + 同宽黑边"的组合（另一张靶纸、贴了黑边的白板）
   与靶纸在单帧上不可分。这是刻意保留的边界——再多判据就要靠纹理，代价是首帧检出率。
3. **极暗或极亮的曝光下二值化会失效**。窗口内的局部对比被压平后，胶带不再比周围暗。

已知但可接受的：屏幕上的一块深色窗口在统计上可能与靶纸几乎一致（方向、厚度、一致性、
框内亮度都过），单帧无法区分；现场靶纸前方不会出现这种结构，且时序一致性会把它排掉。

## 5. 数据结构

`process()` 返回 dict。成功与失败字段不同，消费方必须先看 `valid`：

| 字段 | 语义 |
|---|---|
| `valid` | 本帧是否拿到中心。其余数值字段只在为真时有意义 |
| `stage` | 成功 `full_search`（全图）或 `track`（窄带精修）；失败 `no_black_frame`；空输入 `empty_frame` |
| `u, v` / `raw_u, raw_v` | 中心。新链路无滤波，两者恒等；保留双字段是为了下游不改 |
| `quad` | 规整后的四角，左上起逆时针 |
| `bbox` | 四角的正立外接框 `(x, y, w, h)`，只用于显示 |
| `area` / `aspect` | 胜出候选的面积与对边长度比，直接显示在屏幕上供调参 |
| `band` / `band_ratio` | 暗带得分 / 暗带厚度比；`track` 路径不重复写 `band_ratio` |
| `reject` | 各层淘汰计数 `{contours, area, quad, aspect, band, candidates}` |
| `fail_reason` | 失败原因：`no_proposal` / `all_area` / `all_filtered` / `all_band` / `degenerate` |
| `inner_quad` | **恒为 `None`**。新链路不区分胶带内外沿，绘图层遇到 `None` 跳过 |
| `partial` / `refined_edges` | 兼容字段，恒为 `False` / 恒等于边数；不再有 partial 语义 |
| `masks` / `proposals` | 二值化次数 / 轮廓数，供 `[perf]` 打印；`track` 帧的 `proposals` 为 0 |

`reject` 是本方案最重要的诊断输出：它直接回答"卡在哪一层"，比"有没有检出"有用得多。
`fail_reason` 只是它的浓缩版。`[perf]` 里的 `det_stage=track` 表示这一帧走的是窄带精修，
如果它长期停留在 `full_search`，说明跟踪没有接上，要先查位移门与暗带门。

## 6. 调参顺序

严格按这个顺序，一次只动一个符号：

1. **只看二值图**：`run_pc.py --images <图> --show --stage binary`。目标是**胶带成实心白环、
   纸面成整块黑区、靶纸内的同心圆不再切碎纸面**。胶带被挖空成双线就调小
   `RECT_BLOCK_SIZE`，纸面与外部连通就调大 `RECT_C`。
2. **看淘汰计数**：`diagnose_detect.py <图>`。`area` 占绝大多数说明阈值或面积门有问题；
   `quad` 占多数说明近似精度或目标本身不闭合；`aspect` 占多数说明形状门或目标不是 A4；
   `band` 占多数说明胶带证据没过——先看 `band`/`ratio` 两个读数，再决定动哪一项。
3. **调 `RECT_MIN_AREA`**：从小往大加，先把碎片清掉。
4. **调 `RECT_APPROX_EPS`**：太大多边形退化成三角，太小保留毛刺、点数超过四。
5. **调长宽比**：先宽后窄。倾斜场景必须留余量，不要卡在目标不转时的理论值上。
6. **调暗带四项**：先 `RECT_MIN_BAND_SCORE`（方向对不对），再 `RECT_MIN_BAND_RATIO`
   （宽度够不够），最后 `RECT_BAND_MIN_UNIFORM` 与 `RECT_MIN_INNER_MEAN`。
   现场偏暗时先降 `RECT_BAND_CONTRAST`（比内侧暗多少算暗），不要动占比门。
7. **调跟踪**：`RECT_TRACK_RADIUS_PX` 要覆盖帧间最大位移，`RECT_TRACK_MAX_SHIFT_PX`
   要略大于它；两者都太小会让 `det_stage` 长期停在 `full_search`。
8. **回看结果图**：`run_pc.py --images <图> --output reports/xxx`，确认框与中心稳定。

`RECT_MAX_AREA_RATIO` 一般不要动，它是防"锁整幅"的护栏，不是调优项。

## 7. 与下游的接口

- `aim_control` 只读 `valid / u / v / stage / captured_at`，并自己算 `dx/dy`。
  新链路无滤波，`AIM_USE_RAW` 仍然成立（`raw_*` 与 `u/v` 相同）。
- `draw_result(gray, result, show_width, top_offset)` 签名不变，返回 BGR 画布。
  它读 `quad / bbox / u / v / area / aspect / band`，并在 `inner_quad` 为空时跳过内框。
- `telemetry` 读 `masks / proposals / stage / fail_reason`，字段语义已随新链路更新：
  `proposals` 是"进入形状过滤的轮廓数"，`track` 帧为 0 属正常。
- `target_api` 的 `Result` 字段集合不变，`inner_quad` 为 `None`、`partial` 恒假。

跨模块契约只有一条：**`quad` 必须是四行两列的 ndarray**。绘图层、`target_api` 的四点
输出都直接索引它，改成 list 或改变顺序不会报错，只会画歪。

## 8. 验证方式

| 目的 | 命令 | 看什么 |
|---|---|---|
| 单图跑通 | `tools/run_pc.py --images <图>` | JSON 里的 `valid / center / reject` |
| 看二值图 | `tools/run_pc.py --images <图> --stage binary --show` | 胶带是否成实心白环、纸面是否成块 |
| 逐层归因 | `tools/diagnose_detect.py <图> --save reports/diag` | 各层淘汰计数 + 三张阶段图 |
| 识别回归 | `tools/test_rectangle_detect.py` | 合成靶纸中心误差、旋转竖放、角点重复性、负样本 |
| 全量门禁 | `tools/check_pc.py` | 打包、清单、识别回归、控制与显示类回归 |

`test_rectangle_detect.py` 里的合成图是干净的，只证明几何正确；真实场景的鲁棒性
只能靠 `run_pc` 在实拍帧上看。门禁全绿不等于现场还能识别，这一点必须在改判据时记住。

## 10. 下一轮待填

按优先级排列，都不改变本文的流水线结构：

1. **板端耗时与 `det_stage` 分布**：先确认 30fps 还成不成立、`track` 占比有多高。
   `track` 长期不出现时，问题在位移门或暗带门，不在全图搜索。
2. **判据里别再引入绝对灰度**：上一版用绝对灰度上限量暗带，画面一亮就整帧判负。
   合成扫描已覆盖 0.5~2 倍增益 × 60~400px 目标，现场若仍有失败，先看 `det_fail`
   里附带的 `s=/r=/e=/i=` 读数，判断是哪一项越界，而不是先调门限。
3. **缺失一条边时的降级**：现在靠跟踪跨过去；若要单帧支持，需要"三条边 + 矩形约束"
   反推第四边，并同时给出置信度，避免把先验边当成实测边。
4. **`draw_result` 信息精简**：当前把面积、长宽比、暗带得分、耗时都印在左上角，
   与激光面板可能重叠，上板后按实际屏幕再调。
