# 视觉识别实现说明

本文记录识别链路的**流水线分层、数据结构、参数作用与已知边界**，用于两件事：
现场分阶段调参，回滚时确认边界。

- 系统整体结构与云台链路 → 应用目录 `README.md`
- 参数当前取值 → `config.py`（本文只给符号名）
- 哪一轮改了什么 → git 历史（本文不记流水）

## 1. 范围

识别链路只剩三个文件：

```
camera_source.py     MaixPy 帧 → uint8 灰度 ndarray
rectangle_center.py  二值化 → 轮廓 → 三层过滤 → 对角线交点 → 绘制
aim_control.py       消费 u/v，算偏差、下发串口、驱动闭环
```

`target_api.py` 是这层的对外门面，`vision_worker.py` 负责线程调度，二者不含识别逻辑。

**已删除**（旧判据，不要试图恢复其中的片段）：`contour_locator.py`、`rect_geometry.py`、
`kalman_filter.py`。它们对应的 Canny/Otsu 提案、四边暗带证据、亚像素精修、单应反算、
匀速卡尔曼与运动预测一并移除。需要更强鲁棒性时**新增一层判据**，不要回退到旧结构。

## 2. 流水线

组织原则：**每个小功能都是模块级函数**，只依赖入参、不读类状态；`RectangleCenterDetector`
只保存参数并按顺序调用它们。任何一步都能单独跑、单独测，`diagnose_detect.py` 就是直接调
`blur_frame` / `binarize_frame` / `find_quad_candidates` 三个函数。

| 步 | 入口 | 输入 → 输出 | 参数 |
|---|---|---|---|
| 1 灰度 | `to_gray_frame` | 帧 → `(H,W)` uint8（去哑轴、校验类型） | 无 |
| 2 模糊 | `blur_frame` | 灰度 → 灰度 | `RECT_GAUSS_KERNEL`，置 `(0,0)` 跳过 |
| 3 二值化 | `binarize_frame` | 灰度 → 二值图 | `RECT_BLOCK_SIZE`、`RECT_C` |
| 4 轮廓 + 过滤 | `find_quad_candidates` | 二值图 → 候选列表 + 淘汰计数 | `RECT_MIN_AREA`、`RECT_MAX_AREA_RATIO`、`RECT_APPROX_EPS`、`RECT_MIN/MAX_ASPECT` |
| 5 择优 | `select_largest` | 候选 → 面积最大者 | 无 |
| 6 中心 | `success_result` / `quad_diagonal_center` | 候选 → 四点 + 交点 | 无 |

`locate_result` 把"有候选 / 无候选 / 四点退化"三种情况收敛成一个结果 dict，
`fail_result` 与 `finish_result` 只负责填字段——失败归因与字段补齐都不混进主流程。

**第 3 步是整个链路的地基**。`adaptiveThreshold` 用局部均值做参考、`THRESH_BINARY_INV`
反色，黑胶带因此变成白色环带，白纸与亮背景变黑。窗口小则对光照梯度敏感、大则把细边抹平；
`RECT_C` 小则断边被接上、大则噪点被压掉。这两个参数没调好，后续三层过滤全部白费。

**第 4 步的三层是逐层 `continue`**，不是打分：

1. 面积：小于 `RECT_MIN_AREA` 或大于 `RECT_MAX_AREA_RATIO × 画面` 即淘汰。
   上限那一层是护栏——没有它，整幅墙面或门框会以最大面积胜出。
2. 四边形：`approxPolyDP` 后必须正好四个点。不检查凸性——按约定不出现凹四边形；
   真实遮挡通常连四个点都凑不出来，会在这里被淘汰。
3. 长宽比：正立外接框的 `w/h`。**前提是靶纸横放**——竖放会落到 0.7 附近被拒；
   旋转角度大时外接框趋近正方形、比值也掉向 1。这两种按约定不会出现；
   若现场真的出现，要改判据本身，抬参数解决不了。

**第 5 步**在通过三层的候选里取面积最大者，把它的四个点规整为
`[左上, 右上, 右下, 左下]`，再取两条对角线交点作为中心。

## 3. 为什么中心用对角线交点

正立外接框的中心在目标旋转时会偏：框本身随旋转变大，中心也随之漂移。
四个顶点本来就已经由近似得到，交点计算是几次乘除，成本可忽略，而且**透视下无偏**。

合成靶纸实测（白底 + 黑环 + 光照梯度 + 噪声，同一目标旋转三个角度）：
不旋转时中心与真值完全重合，旋转十几度与二十几度时仍在亚像素级。同期外接框中心
已经出现可见偏移。这条结论是选择交点的唯一理由，不必再引入单应与物理尺寸。

## 4. 已知边界

这些是方案的**原理性边界**，不是参数没调好，调参解决不了：

1. **遮挡与贴边不可用**。胶带被画面边缘裁掉、被物体挡住、或与另一个深色物相连时，
   外轮廓不再是闭合四边形，第 2 层直接淘汰。实拍样本里"上边被灰块遮住"就是这种情况：
   轮廓绕到遮挡物边缘，点数变成八、且非凸，放大近似精度也救不回来。
2. **只支持横放与小角度倾斜**。竖放靶纸的 `w/h` 约为 0.7，直接被长宽比拒；
   旋转到三十度以上，正立外接框趋近正方形，比值会掉到下限以下。这两种属于当前
   约定的使用前提，不是待修缺陷；真要支持，改判据（例如换成对边长度比）而不是抬参数。
3. **更大的深色矩形会抢锁**。判据只有面积、形状、比例，没有"这是不是胶带"的证据。
   画面里若存在更大的深色环（窗框、桌沿、另一个靶），它会赢。
4. **无跨帧稳定**。每帧独立，候选切换时框会跳。这是刻意的取舍：换取可复现与好调试。

若现场被第 3 条咬到，正确的加法是**增加一层亮度证据**（例如环带均值显著低于环内均值），
而不是把长宽比收紧到刚好只过靶纸——后者换个角度就失效。

## 5. 数据结构

`process()` 返回 dict。成功与失败字段不同，消费方必须先看 `valid`：

| 字段 | 语义 |
|---|---|
| `valid` | 本帧是否拿到中心。其余数值字段只在为真时有意义 |
| `stage` | 成功 `full_search`；失败 `no_black_frame`；空输入 `empty_frame` |
| `u, v` / `raw_u, raw_v` | 中心。新链路无滤波，两者恒等；保留双字段是为了下游不改 |
| `quad` | 规整后的四角，左上起逆时针 |
| `bbox` | 正立外接框 `(x, y, w, h)`，长宽比就是按它算的 |
| `area` / `aspect` | 胜出候选的面积与长宽比，直接显示在屏幕上供调参 |
| `reject` | 各层淘汰计数 `{contours, area, quad, aspect, candidates}` |
| `fail_reason` | 失败原因：`no_proposal` / `all_area` / `all_filtered` / `degenerate`（四点共线，对角线无交点） |
| `inner_quad` | **恒为 `None`**。新链路不区分胶带内外沿，绘图层遇到 `None` 跳过 |
| `partial` / `refined_edges` | 兼容字段，恒为 `False` / 恒等于边数；不再有 partial 语义 |
| `masks` / `proposals` | 二值化次数 / 轮廓数，供 `[perf]` 打印 |

`reject` 是本方案最重要的诊断输出：它直接回答"卡在哪一层"，比"有没有检出"有用得多。
`fail_reason` 只是它的浓缩版。

## 6. 调参顺序

严格按这个顺序，一次只动一个符号：

1. **只看二值图**：`run_pc.py --images <图> --show --stage binary`。
   目标是胶带环闭合、噪点可接受。断边就减小 `RECT_C`，噪点多就增大，
   光照梯度大就调 `RECT_BLOCK_SIZE`（保持奇数）。
2. **看淘汰计数**：`diagnose_detect.py <图>`。`area` 占绝大多数说明阈值或面积门有问题；
   `quad` 占多数说明近似精度或目标本身不闭合；`aspect` 占多数说明形状门或目标不是 A4。
3. **调 `RECT_MIN_AREA`**：从小往大加，先把碎片清掉。
4. **调 `RECT_APPROX_EPS`**：太大多边形退化成三角，太小保留毛刺、点数超过四。
5. **调长宽比**：先宽后窄。倾斜场景必须留余量，不要卡在目标不转时的理论值上。
6. **回看结果图**：`run_pc.py --images <图> --output reports/xxx`，确认框与中心稳定。

`RECT_MAX_AREA_RATIO` 一般不要动，它是防"锁整幅"的护栏，不是调优项。

## 7. 与下游的接口

- `aim_control` 只读 `valid / u / v / stage / captured_at`，并自己算 `dx/dy`。
  新链路无滤波，`AIM_USE_RAW` 仍然成立（`raw_*` 与 `u/v` 相同）。
- `draw_result(gray, result, show_width, top_offset)` 签名不变，返回 BGR 画布。
  它读 `quad / bbox / u / v / area / aspect`，并在 `inner_quad` 为空时跳过内框。
- `telemetry` 读 `masks / proposals / stage / fail_reason`，字段语义已随新链路更新：
  `proposals` 现在是"进入三层过滤的轮廓数"，不再是"提案候选数"。
- `target_api` 的 `Result` 字段集合不变，`inner_quad` 为 `None`、`partial` 恒假。

跨模块契约只有一条：**`quad` 必须是四行两列的 ndarray**。绘图层、`target_api` 的四点
输出都直接索引它，改成 list 或改变顺序不会报错，只会画歪。

## 8. 验证方式

| 目的 | 命令 | 看什么 |
|---|---|---|
| 单图跑通 | `tools/run_pc.py --images <图>` | JSON 里的 `valid / center / reject` |
| 看二值图 | `tools/run_pc.py --images <图> --stage binary --show` | 环是否闭合 |
| 逐层归因 | `tools/diagnose_detect.py <图> --save reports/diag` | 三层淘汰计数 + 三张阶段图 |
| 全量门禁 | `tools/check_pc.py` | 打包、清单、控制与显示类回归 |

门禁**不验证识别效果**——识别效果只能靠 `run_pc` 在真实帧上看。这一点必须在改判据时记住：
门禁全绿不等于还能识别。

## 10. 下一轮待填

按优先级排列，都不改变本文的流水线结构：

1. **亮度证据层（第四层）**：环带均值 vs 环内均值，挡"更大的深色矩形抢锁"。
   位置在长宽比之后、选最大之前，失败计入 `reject`。
2. **候选排序**：现在单纯按面积取最大。可改为"面积 × 形状得分"，让接近目标长宽比的
   候选优先，减少同画面多候选时的跳变。
3. **板端耗时核对**：在 MaixCAM2 上看 `[perf]` 的 `det_ms`。全图 `adaptiveThreshold`
   的开销与画面内容无关，是最需要实测的一项。
4. **`draw_result` 信息精简**：当前把面积、长宽比、耗时都印在左上角，与激光面板可能重叠，
   上板后按实际屏幕再调。
