## 3 逐条证据与根因

### 3.1 抖动 / 轻度拉长变形 —— 基本解决

连续 40 帧、含 σ=3 噪声：

| 场景 | valid | track | 最大误差 | 中位误差 |
|---|---|---|---|---|
| rot±1° + 各向异性 1.2% + 平移±2.5px + 逐角±3.5px | 40/40 | 39/40 | 1.43px | 0.033px |
| 各向异性 5%（拉长） | 40/40 | 39/40 | 0.07px | 0.037px |
| 各向异性 10% | 40/40 | 39/40 | 0.05px | 0.027px |
| 剪切 0.08 | 40/40 | 39/40 | 0.07px | 0.036px |
| 组合（5% + rot1° + 逐角 3px） | 40/40 | 39/40 | 0.08px | 0.030px |
| 真机 `real_board_frame.png` 仿射抖动 | 40/40（seq）/ 40/40（fresh） | — | — | — |
| 真机 `real_scene_corner_gap.png` 仿射抖动 | 39/40（seq）/ **27/40（fresh）** | — | — | — |

判定依据：拉长 5~10% 不再导致丢失，`_refine` 的共线硬门限已按 v1.0.1 正确移除。
**残留风险**：`corner_gap` 这张真机帧在"没有历史位置"时的单帧召回只有 67.5%。
连续帧靠 track 兜住了，但**首帧捕获与复锁仍然依赖它**，这会在问题 3 上放大代价。

### 3.2 复杂环境 —— 未解决，失效形式是"误锁"而不是"找不到"

- 真实照片背景（`negative_e421/e880`）上贴靶：6/6 检出，误差 ≤0.33px → **真靶本身找得到**。
- 但纯干扰帧：
  - 随机空心窗框 20 帧 → **20/20 判为有效靶**
  - 随机网格 10 帧 → **10/10 判为有效靶**
- 抓到一个具体案例：94×123px 的空心矩形，`kind=inner`，四边覆盖率 `[1.00, 0.96, 0.79, 0.96]`，直接通过。

根因（`vision/rectangle_center.py:90-170` `_verify`）：
1. 只验"四条边内侧有一条暗带、再往里是亮的"，**不验内框/外框面积比、不验内部结构**。
2. 暗带宽度是**假设值**：采样点固定在 0.20/0.40/0.60×18mm，只要求这几处是暗的。
   实际胶带厚度在 **约 11~21mm** 之间都会被接受，并不校验内沿真实位置。
3. `config.py:176-179` 的 `MIN_ANGLE_DEG / MIN_INNER_RATIO / MAX_INNER_RATIO / DARK_CENTER_MIN`
   是**死参数**——全仓 `.py` 零引用（只在 `config.py` 和 `test_performance.py` 里被赋值）。
4. 真机帧里靶纸有明显的**同心印刷环**（见 `tools/real_board_frame.png`），这个最强判别特征目前完全没用。

为什么门禁没发现：现有负样本是空白、实心黑块、2 张真实照片；
`test_performance.py` 只断言"实心亮/暗矩形不被接受"——空心框从未进过测试集。

### 3.3 附近复锁 —— 能锁，但每次都付全图搜索的代价

实测（锁定 → 5 帧空白 → 目标平移）：

| 位移 | 复锁 | 帧数 | stage |
|---|---|---|---|
| 25 / 50 / 80 / 120 / 160px | 全部成功 | 1 帧 | **full_search** |

根因（`vision/rectangle_center.py:440-448`）：`_roi_retry` 是**一次性闩锁**。
丢失后的**第一个空白帧**就会把局部 ROI 搜索用掉并置 `False`，之后所有帧只能全图搜索。
对照实验：每帧把 `_roi_retry` 复位 → 同一场景 `stage=roi_search`、同帧命中。

板端含义：PC 上 full_search 3~23ms，板端 **0.3~1.4s**（`存档/项目自检/板端故障排查_2026-10-18.md`）。
`RESULT_MAX_AGE_S = 0.20`（`config.py:32`）→ **全图搜索的结果在结构上一定是 stale**，
`aim_control.py:242-246` 于是每帧 `_stop_motion` → 云台站住不动。
这就是"丢一次要等很久、云台像卡住"的机制。

### 3.4 云台移动 —— 未解决

按实机节拍（采集间隔固定 25ms，`timestamp=captured_at`）重测：

| 位移/帧 | 运动模糊 | valid | track | 最大中心误差 |
|---|---|---|---|---|
| 12px | 0 | 30/30 | 29/30 | 0.98px |
| 24px | 0 | 30/30 | 26/30 | 0.08px |
| 24px | 9px | 30/30 | 26/30 | 2.30px |
| 60px | 0 | 30/30 | 21/30 | 0.08px |
| 60px | 21px | 30/30 | **4/30** | **11.49px** |
| 90px | 15px | 30/30 | **0/30** | 1.17px |

结论分两层：
- **不丢目标**（valid 30/30），但**大量帧退回搜索态**。板端每次退回 = 0.3~1.4s + stale + 停云台。
- 两个独立瓶颈（已用参数扫描定位）：
  1. `PREDICT_MAX_PX = 60`（`config.py:165`）截断预测：90px/帧时预测被砍到 60，残差 30px > `TRACK_RADIUS=12`。
     实测把上限提到 120：90px 从 0/30 → 6/30，120px 从 0/30 → 14/30。
  2. `TRACK_RADIUS = 12`（`config.py:159`）容不下残差：60px+21px 模糊时 12→4/30、20→11/30。
  3. 运动模糊本身让窄带梯度峰变平，亚像素插值失效（误差 11.5px 就是它）。

另有一条独立缺陷——**目标一旦部分出画就整帧拒绝**：
`_verify` 要求所有采样点都在图内（`rectangle_center.py:128-131`），任一点越界 `return None`。
实测平移 160px 仍正常，180px（右边缘越界约 15px）立即 `no_black_frame`。
云台大幅摆动时靶纸贴近画面边缘是常态，这条会造成**突变式丢失**。

### 3.5 云台转动 —— 控制逻辑完整，但换算系数从未标定

控制侧（`vision/gimbal_aim.py`）该有的都有：状态机 BOOT/COARSE/FINE/SETTLE/HOLD/SCAN/FAULT、
单帧限幅、死区、离群拒收、指令限频、发散保护、运动完成等待、ACK/E2 看门狗。
**逻辑上能转**，离线回归也覆盖了。

但存在两个会直接毁掉现场手感的问题：

**（1）像素→脉冲系数是占位值**
`config.py:63-64` `PULSE_PER_PX_YAW = PULSE_PER_PX_PITCH = 3.67`，行内注释就是
"必须用实机开环标定替换"。而 `GIMBAL_CALIBRATED = True` 让程序完全信任它。
按项目自述的成像比例（165cm 处 0.1cm ≈ 0.67px ≈ 0.052°/px、直驱 8.89 脉冲/度），
几何上应约 **0.46 脉冲/px**；若真如此，则 3.67 偏大约 **8 倍**，单帧修正比例
= 3.67×GAIN(0.30)/0.46 ≈ **2.4 > 1**，必然过冲振荡——**与"云台一动就丢"的现象高度吻合**。
若机构带约 8:1 减速，则 3.67 恰好合适。**这一点只能靠 5 分钟开环标定定案，不能靠推断。**

**（2）文档里的"主调参数"已不存在**
`AGENTS.md` §3.1 与 `README.md:1426` 都写"主参数 `DEG_PER_PX_*=0.30`，置 0 回退 `PULSE_PER_PX_*`"。
实际 `DEG_PER_PX_*` / `PULSES_PER_DEG_YAW` **在配置里已被删除**（`YAW_PULSES_PER_DEG=0.0`），
`gimbal_aim.py:205` 只读 `PULSE_PER_PX_*`。按文档调参**完全无效**。

另外两处"双份真值"容易误判：
- `config.py` 里写 `GAIN_YAW=0.5 / MAX_STEP_PULSES=360 / RPM_FINE=300 / RPM_COARSE=1200`，
  但类定义后立即 `apply_aim_profile(Config)` 把它们覆盖成 **0.30 / 80 / 60 / 150**（`AIM_PROFILE="smooth"`）。
  现场读 config 会读错。
- `DEADBAND_PX = 1.0`（`config.py:67`），长期记忆里记的是 3.0。1.0px 若小于机械回差，
  会在齿隙里来回找；需要用回差实测值反过来定。

## 4 下一轮方案（按优先级，含验收口径）

### P0 · 云台换算标定（先做，纯标定，零代码风险）

1. 靶纸固定，读初始 `(u,v)`；屏幕点 `SELF-TEST` 发 400 脉冲；再读 `(u,v)`。
   `PULSE_PER_PX_隔轴 = 400 / Δpx`（yaw 用 u 方向，pitch 用 v 方向）。
2. 同一动作反方向 400 脉冲回原位：偏差 = 机械回差 → `DEADBAND_PX ≥ 1.5×回差`。
3. 正向给 20px 误差，看误差是否**减小**；变大则翻 `DIR_SIGN_*`。
4. 回填 `config.py:63-67`，并把 `GIMBAL_CALIBRATED` 的真实含义（"已按实机标定"）落实。

**验收**：单帧修正比例 = `PULSE_PER_PX × 0.30 ÷ 实测脉冲/px` 落在 **[0.2, 0.6]**。
> 0.6 会明显过冲；> 1 必振荡。这是判"云台能不能用"的唯一硬指标。
**同步**：删掉 `AGENTS.md` §3.1 / `README` §1426 里 `DEG_PER_PX_*` 的说法，
改成实机 `PULSE_PER_PX_*`，并把 `apply_aim_profile` 的覆盖关系写进注释。

### P1 · 复杂环境误锁（最高优先视觉项）

改动集中在 `_verify`，做"三选二"而不是单一硬门限：

1. **启用死参数**：`MIN_INNER_RATIO=0.62 / MAX_INNER_RATIO=0.80`（A4 理论值 0.726）。
2. **实测胶带内沿**：沿四边法向找亮度反转点，反算 mm，要求 `18 ± 3mm`
   （替代现在"11~21mm 都收"的隐式宽容）。
3. **内部结构**：正视面径向剖面找 ≥2 条暗环（真机帧有 4 条同心圆）；
   或退化为"内部亮度标准差 ≥ 阈值 + 中心区不得整片暗"（`DARK_CENTER_MIN` 的本意）。
4. **search 路径 2 帧确认**：仅当 `rank` 落在边缘带时启用，避免拖慢每帧。

**新增负样本入库**（关键，否则下次还会回归）：20 帧空心窗框 + 10 帧网格写入
`tools/`，`test_real_scene.py` 断言 **0 误检**。
**验收**：空心框 0/20、网格 0/10；`negative_e421/e880` 仍拒；真机 board/corner 仍检出；
`test_images_e2e` 16/16 不回归。

### P2 · 复锁与搜索代价

1. `_roi_retry` 从"一次性"改成 **丢失期间每帧可试、上限 3 次**；
   ROI 由"上一帧外框"扩到"上一帧外框 ∪ 预测位置"，`ROI_PADDING` 0.20 → 0.35。
2. `_search` 候选排序从"面积降序"改为"长宽比接近 1.414 + 暗带预筛"打分，
   避免大窗框抢占前 8/16 个候选位。
3. 板端压时延：`SEARCH_WIDTH 320→240`、只在 ROI 内做 Canny、候选先做低频暗带预筛。
   目标 **full_search < 200ms**，让 `RESULT_MAX_AGE_S=0.20` 不再结构性失效。

**验收**：真机 corner 100px 复锁 ≤2 帧且 `stage=roi_search`；板端 `[perf] det_ms < 200`（full_search）。

### P3 · 运动与运动模糊

1. `TRACK_RADIUS 12 → 20`（实测 60px+21px：4/30 → 11/30；24px+9px：26 → 27/30）。
2. `PREDICT_MAX_PX 60 → 120`（实测 90px：0 → 6/30；120px：0 → 14/30）。
3. 预测改**多假设**：上一帧位置 / 外推位置 / 零速度 / 反向，任一假设精修通过即接受
   → 云台换向那一帧不再整帧掉。
4. 运动模糊：`_refine` 的可选梯度换 3×3 Sobel 或沿模糊方向的 1D 反卷积；
   线模型加"上一帧直线做先验"的跨帧加权。
5. 可选：`ENABLE_IMU_FEEDFORWARD`（当前 False）用云台角速度预测目标位移。

**验收**：60px/帧+21px 模糊 `track ≥25/30`、中心误差 ≤2px；90px/帧 `track ≥20/30`。

### P4 · 部分出画

`_verify` 的"任一点越界即整帧拒"改为**逐采样点丢弃**：
要求 ≥3 条边、每条边 ≥50% 采样有效，中心由剩余边求交；
`geometry_consistent` 标志保留（精度降级要可见）。

**验收**：目标 30% 出画仍 valid、中心误差 ≤2px；回到画内 1 帧恢复 `track`。

### P5 · stale 时不要无条件停机

`aim_control.py:242-246` 现在一旦 stale 就 `_stop_motion`。
建议：stale 的前 2~3 帧用最近一次有效速度**外推保持**（新增 `AIM_STALE_HOLD_FRAMES`），
之后才停。避免"搜索慢 → 停机 → 相对运动更大 → 更找不到"的级联。
> 这项要在 P0 标定完成后再开，否则会掩盖方向/比例错误。
