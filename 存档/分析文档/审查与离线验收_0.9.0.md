# v0.9.0审查与离线验收

交付构建：`2026-10-18-subpixel-verified-v0.9.0`。
输入是用户提供的v0.8.0解压目录，没有Git元数据。本轮建立本地原始快照`efe5a61`，
修正B轨`maixcam2_rect_center`；A轨运行源码未修改。
用户已确认本轮先交付离线验证结果，不连接实际设备。

## 审查发现与修正

| 问题 | 影响 | 本轮修正 |
|---|---|---|
| 精修沿法向取整数位置后拟合 | 亚像素平移时发生量化，旧30场景最大误差0.691px | 对未加距离惩罚的真实梯度峰做抛物线插值，再做Huber直线拟合 |
| 精修失败仍返回粗候选 | 中心可能取自低分辨率轮廓 | 至少一次完整精修成功；失败继续验证其它候选 |
| 允许第四边完全无证据 | U形开口也能输出有效框 | 四条边都需当前帧足够的共线采样点；整边缺失返回无效 |
| 胶带暗带验证没有直线残差门限 | 椭圆环被拟合为四边形并误检 | 原图每边至少55%采样共线，残差默认≤0.8px |
| 用黑色环轮廓面积提前做尺寸过滤 | 小靶反光使环开口，轮廓面积骤降而漏检 | 尺寸过滤改用恢复后的四边形面积；最小面积比0.008，仍须通过四边验证 |
| 相机与显示均限制30fps | 无法超过30fps | 默认请求40fps，25ms采图周期；保留真实完成事件计数 |
| 将旧检测结果画在实时新帧上 | 移动时看起来中心偏移 | 快照保留自己持有的原始灰度帧，几何与画面配对 |
| 所有检测都计入detect_fps | 无靶时高速搜索也可能被误读为有效识别帧率 | 另外统计valid_fps、识别加控制P95；图传统计成功发送计数 |
| WebSocket逐字节Python异或 | JPEG吞吐较高时增加CPU开销 | 预计算64KB异或表，使用C层translate；图传进程降低CPU优先级 |
| Windows子进程默认GBK输出 | 数学符号触发UnicodeEncodeError，整套门禁中断 | check_pc统一对子进程使用UTF-8 |
| 原测试会重复喂同一图直到成功 | 隐藏首帧漏检和重捕获漏帧 | 原30场景和新增76场景全部单次调用，运动帧也不得重试 |

## 几何与控制API

| API | 用途 | 关键返回值 |
|---|---|---|
| `detect_black_frame(frame)` | 单帧独立搜索 | `valid/raw_center/quad/inner_quad` |
| `CenterTracker(with_laser=True).track(frame, now)` | 连续跟踪和固定激光偏差 | `raw_center/dx/dy/aim_valid/stage/captured_at` |
| `fixed_laser_error(result, cfg=None, laser_uv=None)` | 无图像运算地计算固定点偏差 | `(dx,dy)`或`None` |
| `AimLoop(cfg).step(frame, now)` | 识别、偏差、串口闭环 | `aim_state/cmds`；需`close()`释放资源 |
| `load_config(**overrides)` | 按任务覆盖参数 | 独立派生配置，不改磁盘 |

```python
from target_api import CenterTracker, fixed_laser_error

tracker = CenterTracker(with_laser=True)
result = tracker.track(gray, now=capture_time)
if result and result.aim_valid:
    print(result.raw_center, result.dx, result.dy)
    assert fixed_laser_error(result) == (result.dx, result.dy)
```

所有坐标都在输入原始图像坐标系。当前标定分辨率640×480，固定激光点`(294,202)`。
`dx=raw_u-294`、`dy=raw_v-202`；正值分别表示靶心在激光右侧、下方，电机方向另外由`DIR_SIGN_*`映射。
`u/v/center`供显示平滑；`raw_u/raw_v/raw_center`供闭环。
默认每轴1px死区。固定点越界、非有限中心和无效目标不产生偏差。
换安装、分辨率或标定距离后必须重新确认固定点及脉冲比例；本轮没有把既有3.67脉冲/px称作实测。

## 精度与负例验证

| 验证 | 结果 | 证据范围 |
|---|---|---|
| 原几何回归30场景 | 30/30，最大中心误差0.084px | 单帧、独立OpenCV真值 |
| 同一扩展集改前/改后对比 | 检出67/76→76/76；负例误检2/9→0/9 | 使用原始快照源码独立运行完全相同的76张输入 |
| 新增抗锯齿场景76张 | 76/76，最大0.489px，P95约0.106px | 4倍面积采样；旋转、反光、低对比、噪声、模糊、暗背景、48px起小靶、强透视及靠近边缘 |
| 连续运动120帧 | 120/120，最大0.302px；119帧窄带跟踪 | 40Hz时间戳，含连续变向；首帧全图捕获 |
| 负样本9张 | 0误检 | 3种纯色、实心块、U形、椭圆、随机噪声、2张已有真实负样本 |
| 图像到电机闭环仿真 | 65帧、15条轴命令；最终两轴误差约0.844/0.868px | 调用实际AimLoop；模拟机械响应，非实机命中验收 |

真值只通过独立`cv2.getPerspectiveTransform/perspectiveTransform`得到，不使用被测单应代码。
PNG输入、标注结果、完整JSON和HTML报告均可重新生成。
报告白色叉号为真值，蓝色十字为输出中心；同一张静态图仅检测一帧，不以等待多帧掩盖漏检。

## 算力分配与帧率验收

| 环节 | 执行策略 | 上限/观察指标 |
|---|---|---|
| 稳态识别 | 4条原分辨率窄带；批量采样、稳健拟合 | 0张分割掩膜 |
| 搜索/重捕获 | 320宽Canny，必要时补Otsu；轮廓和候选数有界 | 每次≤2张，ROI失败同帧全图，单帧累计≤4张 |
| 投影解算 | 保留归一化双精度8×8方程，OpenCV原生LU消元 | 缓存物理矩形、采样模板、法向偏移，减少Python/NumPy小调用 |
| 跨线程 | 先复制相机缓冲，单槽保留最新帧 | 丢弃待处理旧帧，避免排队延迟 |
| 固定激光偏差 | 两次减法，不做光斑检测 | 无图像检测开销 |
| 识别与UART | 单个识别线程拥有UART | 完成运动后等新观测；不重复执行旧结果 |
| 本地显示 | 主线程绘制，两张画布池，显示线程show | 慢show丢预览，不阻塞采图 |
| JPEG/图传 | 独立进程、单槽mmap、单线程OpenCV、较低CPU优先级 | `[stream-perf] fps`只计成功发送 |

同进程交替执行400次A/B跟踪，排除前21帧计时：本机一次记录中位数3.254→2.612ms，
P95为5.764→4.533ms，约减少20%跟踪耗时。不同批次会受主机负载影响，原始计时JSON随报告交付。
这些数字只用于PC改动前后对比，不是板端帧率。

`benchmark_board.py`默认用真实相机、识别线程、本地显示和图传运行20秒。
四路完成吞吐均须>30fps才通过；`valid_detection`仅统计有效检测，图传未连接不可能通过默认验收。
该脚本不构造电机链路。其采图时间以read完成时的本机时钟为准，实际曝光/SDK缓冲延迟仍需上板测量。
真实设备的曝光、镜头畸变、遮挡、机械回差和网络状态不能由PC仿真消除。
