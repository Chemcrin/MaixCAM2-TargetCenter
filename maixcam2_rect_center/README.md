# MaixCAM2 黑框中心识别与双轴云台瞄准

应用目录内唯一文档：说明这套系统**是什么结构、各部分管什么、关键机制为什么这样设计**。
具体数值与当前状态看 `config.py` 和代码注释；协作流程看仓库根 `AGENTS.md`；全部文档的入口看 `docs/README.md`。

## 1. 任务与思路

2025 电赛 E 题：识别 A4 靶纸上的靶心，引导云台上的激光指向。
靶心是红色记号笔点，在 165cm 处不足 1px，物理上不可见——因此不走"找红点"，
而是用靶纸四周的黑胶带框反算：

- **找框**：降采样到长边 320 → 整幅一次 Otsu（本次扫描没有确认目标才退化到自适应阈值）
  → 连通域 + 多边形逼近出四边形提案。暗块外轮廓与亮面补集各做一轮提案，
  闭合的暗带环因此有两次机会。
- **验证**：把 A4 纸面 + 胶带的物理矩形按**真实带宽**向内外各取两点，
  要求"暗带两点都暗、纸面一点明显更亮"，四条边里至少三条达标。
  带宽因此成为判据：显示器窄边框、印刷细环、洞洞板、门框在结构上就过不来。
  代价是**现场胶带宽度必须与 `BLACK_FRAME_MM` 一致**，换胶带不改配置会稳定拒检。
- **定中心**：内框（纸边）四角的对角线交点。胶带上下不等宽时外框中心会偏出半个带宽，
  纸边不会；透视下每条边仍是直线，四线交角是几何精确解，不需要逐帧 warp。
  精修阶段沿每条边取一排法线灰度、取梯度极值拟线再求交，把提案的降采样误差压到亚像素；
  精修不通过就退回提案值，不拿单帧失败换掉锁。
- **抗丢锁**：锁定后只在上帧框附近的 ROI 里重复同一套判据，失败才回全图重搜；
  重搜在同一帧内完成，不拿上一帧的角点冒充本帧测量。
- **输出**：内框四角的对角线交点，即靶心。

纸面上的同心圆**不参与**这条链路：实际场景里它又细又淡，距离一远基本看不见，
拿它当判据会让识别随距离时好时坏。环的定位按另一条独立任务处理（固定云台角度）。

## 2. 代码结构（4 层 + 入口）

```
main.py              入口桩（属逻辑层）：sys.path 引导 → vision.logic.run
config.py            全部可调参数，现场只改这一个文件（层外共享，四层只读）
target_api.py        对外门面（属逻辑层）：detect_black_frame / CenterTracker / AimLoop
vision/poll.py       ① 轮询层：取帧 → 灰度、帧率计、识别线程（时间轴 B）
vision/algo.py       ② 算法层：纯函数（几何 / 采样模板 / 四边形判据 / 偏差）
vision/logic.py      ③ 逻辑层：结果契约 + 检测器（提案-验证-精修） + 闭环决策 + 主循环
vision/output.py     ④ 执行层：绘制 + 激光面板 + 显示线程（时间轴 C）+ ZDT 协议 + 下发
tools/               门禁与 PC 复现脚本：check_app / check_pc / build_single / run_pc（不进应用包）
```

`vision/` 刻意只留 4 个文件，**一个文件就是一层**，文件名即层名：

| 文件 | 层 | 一句话职责 | 硬约束 |
|---|---|---|---|
| `poll.py` | ① 轮询 | 把画面安全搬进识别线程 | 不产生识别判据；跨线程必须 copy；不 import 其余三层 |
| `algo.py` | ② 算法 | 几何、采样模板与偏差 | 纯函数：无状态、无 I/O、不读 `config` |
| `logic.py` | ③ 逻辑 | 决定该做什么 | 不调 `link.*`，只产出 `commands` 决策值 |
| `output.py` | ④ 执行 | 画到屏幕、把误差变成电机动作 | `link.move` / `link.stop` **只允许出现在这里** |

依赖方向单向：`poll ← algo ← output ← logic`（箭头指"被依赖"），反向一律禁止。
反向依赖属评审否决项：`check_app.py` 只核对包内清单与语法，不做依赖图检查，
改 `vision/` 时按上表逐条自查。

顶层不 import maix（`StepperLink`/`Preview` 构造时才 import），因此 4 层全部能在 PC 上导入与离线验证。

## 3. 三条时间轴

```
相机帧 ──► FramePoller ──► LatestFrameWorker（识别线程）
                              │  VisionControl.process()
                              │    ├─ RectangleCenterDetector → (u,v)
                              │    ├─ deviation → dx,dy
                              │    └─ GimbalAim → apply_commands → 串口
                              ▼
                         最新结果槽 ──► Preview.show 线程（只画，不控制）
```

- **A 采图**（主线程）：`cam.read()` → 可选镜头校正 → 灰度；`captured_at` 在 `read()` 后**立刻**取。
- **B 识别+闭环**（`rect-vision` 线程）：最新帧优先，忙时丢旧帧；**串口归它独占**。
- **C 显示**（`display` 线程）：`show()` 慢只掉预览帧，绝不拖慢 A/B。

跨轴只传"带时间戳的最新结果"；采图时刻算起超过 `RESULT_MAX_AGE_S`（0.20s）的结果
**不画框、不下发指令**，`[perf]` 里 stage 会被替换成 `stale`。

## 4. 识别链路

两态：**搜索**（未锁定，全图降采样出提案）与**跟踪**（已锁定，先在上帧框附近沿边精修，
失败再回 ROI/全图重搜）。判据本体一致，三段各有分工：

| 阶段 | 做什么 | 关键点 |
|---|---|---|
| ① 提案 | 降采样到长边 320 → Otsu（无确认目标再试自适应阈值）→ 闭运算 → 连通域 → 多边形逼近 | 一次 `findContours` 拿全部块，省掉几百次 Python 级调用；暗块轮廓与亮面补集各一轮 |
| ② 验证 | 物理矩形（A4 + 胶带）四边按真实带宽取"暗-暗-亮"三点 → 带宽/亮度/覆盖率/形状门 | 带宽进入判据，细边框与"没有闭合暗带"的物体被结构性排除；允许一条边偏弱（遮挡/反光） |
| ③ 精修 | 当前帧沿四边取法线灰度 → 梯度极值 → 每边 `fitLine` → 相邻求交 | 亚像素；残差超限即放弃精修并退回提案值，不因单帧抖动丢锁 |
| ④ 定心 | 内框四角的对角线交点 | 胶带上下不等宽时外框中心会偏出半个带宽；纸边交点才是靶心 |

- **为什么取内框**：胶带上下宽度常不相等（还有阴影），外框中心会偏出半个带宽；
  纸边与印刷图案同心，靶心永远取纸边四角的对角线交点。
- **带宽是硬约束**：`BLACK_FRAME_MM` 必须等于现场胶带实测宽度（双向门：过窄过宽都拒）。
  换胶带规格、或远处成像把黑带压到 2~3px 时，先改这个值再怀疑其它参数。
- **已知边界**：正方形框（长短边比≈1）、靶纸大半出画都拒——前者与"方形显示器/窗格"共用形状门，
  后者没有完整框就没有真值；"亮面被暗边包住"且带宽/尺寸恰好落窗的东西仍可能被认，
  这是只认框的固有短板，靠场景约束解决，不在本链路内加图案判据。
- **运动模糊**：闭运算桥细断带；仍断则跟踪态下帧沿边精修会先失败、再由 ROI 重搜接上。
- **合成图通过不代表真机可用**：上板前必须用真机帧逐帧复核（`run_pc.py --images`）。

## 5. 云台链路

| 环节 | 位置 | 关键设计 |
|---|---|---|
| 协议帧 | `output.cmd_*` | 0x6B 校验、大端参数、0xFD 相对位置；纯函数可逐字节回归 |
| 双串口链路 | `output.StepperLink` | 非阻塞收发 + ACK/E2 看门狗（**按轴独立武装**） |
| 闭环 | `logic.GimbalAim` | 脉冲 = 误差px × `PULSE_PER_PX` × `GAIN`；死区/限幅/离群拒收/发散看护 |
| 仲裁与下发 | `logic.VisionControl` → `output.apply_commands` | 串口唯一所有者；停机失败立即终止决策链 |

轴映射与方向的**实机定案**（哪个串口是 yaw、正方向朝哪、pinmap 注意事项）
见仓库根 `AGENTS.md` §2——接错轴闭环必发散，动硬件前先读那张表。

> 本版本**不含**失锁扫描、自动标定、IMU 前馈与屏幕按钮。MaixVision 图传走独立进程
> （`vision/maixvision_stream.py`，`SHOW_STREAM` 控制），不占识别线程。

## 6. 入口、配置与对外 API

- `main.py` 只做装配与主循环；一切可调项在 `config.py`。
- `config.py` 末尾的 `apply_aim_profile(AIM_PROFILE)` 会在加载时**覆盖**六个增益/转速/限幅值——
  改手感先看它，别直接改被覆盖的字面值（机制详见 `AGENTS.md` §3.1）。
- `target_api.py` 是对外 API：`detect_black_frame` / `CenterTracker` / `AimLoop`，
  供其他小问直接复用，不依赖屏幕与云台硬件（云台部分可选）。

## 7. 上板与排障入口

- 板端日志 `[rect-center] <BUILD_ID>` 必须与本地逐字一致，否则跑的是旧代码；
- `[perf]` 日志看各阶段耗时；帧率异常先查新鲜度门链路；
  锁定后 `stage=plane_frame`，`search_mode` 区分本帧来源（`track` / `roi_search` / `full_search`）；
  未锁定时看 `det_fail=`：`no_proposal` 是画面里连候选块都没有（阈值太紧或画面太空），
  `all_filtered` 是有候选但带宽/亮度/覆盖率/形状门没过——两者改法完全不同；
- 行尾 `det_split=prep/comp/quad` 是三段耗时：`prep` 是降采样/阈值/提案，
  `comp` 是窄带验证，`quad` 是四边精修。哪段大调哪段；
- 判不出来先看二值图（`run_pc.py --stage binary`）：黑带是否闭合、带宽是否与
  `BLACK_FRAME_MM` 相当；带宽量不对时改配置，别先放宽覆盖率门；
- 屏幕/窗框被误认成靶纸时，收紧 `RECT_ASPECT_MIN/MAX` 或提高 `MIN_EDGE_COVERAGE`；
  本链路不提供"是不是靶纸"的判据，别在这里加图案识别；
- 云台不动先看 `[gimbal]` 的 pinmap readback 与 `[aim] state=`；方向反了看 `AGENTS.md` §2。
