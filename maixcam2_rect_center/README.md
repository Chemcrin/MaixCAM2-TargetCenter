# MaixCAM2 黑框中心识别与双轴云台瞄准

应用目录内唯一文档：说明这套系统**是什么结构、各部分管什么、关键机制为什么这样设计**。
具体数值与当前状态看 `config.py` 和代码注释；协作流程看仓库根 `AGENTS.md`；全部文档的入口看 `docs/README.md`。

## 1. 任务与思路

2025 电赛 E 题：识别 A4 靶纸上的靶心，引导云台上的激光指向。
靶心是红色记号笔点，在 165cm 处不足 1px，物理上不可见——因此不走"找红点"，
而是识别靶纸四周 1.8cm 黑胶带构成的矩形，用矩形中心（经透视校正）作为靶心像素坐标。

## 2. 系统总览

```
相机帧 ──► vision_worker（识别线程，只保留最新帧）
             │
             ├─► rectangle_center   黑框矩形 → 靶心 (u,v)
             │      └─ laser_spot   光斑位置（默认固定标称值）
             │
             └─► aim_control ──► gimbal_aim ──► stepper_link ──► 双轴云台
                     │                │
                     │                ├─ gimbal_search / gimbal_self_test / gimbal_calibrate
                     │                └─ imu_heading（可选航向补偿）
             preview / maixvision_stream（显示与图传，不参与控制）
             app_runtime（装配以上全部，退出时有序释放）
```

系统按**三条独立时间轴**运转（详见 `vision/app_runtime.py`）：
A 采图+识别、B 追踪+闭环、C 显示/图传。
跨轴只传递"带时间戳的最新结果"，过期结果整体判废、不进闭环（新鲜度门，`RESULT_MAX_AGE_S`）。

## 3. 识别链路（`vision/`）

| 模块                    | 职责             | 关键设计                                             |
| --------------------- | -------------- | ------------------------------------------------ |
| `vision_worker.py`    | 识别工作线程 + 最新帧槽位 | 主线程只投递不等待；识别永远只算最新一帧                             |
| `rectangle_center.py` | 识别内核           | 自适应反色二值化 → 内孔/外环轮廓 → 四层过滤 → 择优 → 四边精修/窄带跟踪 |
| `laser_spot.py`       | 光斑读数           | 默认 `LASER_MODE="fixed"` 不检测，只算常量偏差                   |


单帧流水线固定五步，每步可单独出图验证（`run_pc.py --stage binary`）：

- **二值化是地基**：`adaptiveThreshold` 反色后黑胶带变白环。窗口与常数决定环是否闭合，
  这两个没调好，后面的过滤全部白费。
- **轮廓连同内孔一起取**：黑框与桌面、窗框这类暗结构相连时，最外层轮廓会被整块吞掉；
  黑框围出的纸面是独立内孔，不受连通影响，是靶纸最稳定的边界。
- **四层过滤是判据**：面积（含防止锁整幅的上限）→ 四边形（`approxPolyDP` 四点，
  凑不出时退用最小外接矩形）→ 长宽比（**四边形自身的对边长度比**，与朝向无关）
  → 胶带证据（边界外侧是否暗于内侧、暗带够不够宽、四边是否同宽）。
  逐层 `continue`，淘汰计数进结果里的 `reject` 字段。
- **中心是对角线交点**：四点已由近似得到，交点透视下无偏，不用外接框中心。
- **跨帧只做两件事**：锁定后用上一帧的四边做窄带一维搜索（快、端点连续，定期回全图防漂移）；
  丢锁后用上一帧位置给候选排序，超过 `RECT_PRIOR_FRAMES` 就放弃先验。单帧判据本身不变。
- **已知边界**：纸面缺口过大（遮挡把胶带环打断）时整帧判负，靠跟踪跨过去；
  画面里存在"白亮面 + 同宽黑边"的物体（例如另一张靶纸）仍会抢锁。
  取舍与补法见 `docs/视觉识别实现说明.md`。

## 4. 云台链路（`vision/`）

| 模块 | 职责 | 关键设计 |
|---|---|---|
| `stepper_link.py` | ZDT Emm_V5.0 双串口链路 | 协议帧构造 + 非阻塞收发 + ACK/E2 看门狗 |
| `aim_control.py` | 串口唯一所有者 + 优先级仲裁 | 自检/标定/搜索/闭环谁在用串口；采图帧新鲜度门 |
| `gimbal_aim.py` | 增量比例闭环 + 状态机 | 脉冲 = 误差px × `PULSE_PER_PX` × `GAIN`；死区/限幅/发散保护 |
| `gimbal_search.py` | 按钮触发的非阻塞搜索 | 取消即原地停，永不回原点 |
| `gimbal_self_test.py` | 固定脉冲 4 步自检 | pitch 上→下、yaw 左→右；不依赖标定 |
| `gimbal_calibrate.py` | 开环标定 | 实测 `PULSE_PER_PX` / `DIR_SIGN` / 交叉项 / 回差 |
| `imu_heading.py` | 相对陀螺航向 | 非绝对罗盘；原生 I/O 单一所有者 |

轴映射与方向的**实机定案**（哪个串口是 yaw、正方向朝哪、pinmap 注意事项）
见仓库根 `AGENTS.md` §2——接错轴闭环必发散，动硬件前先读那张表。

## 5. 显示与装配（`vision/`）

| 模块 | 职责 |
|---|---|
| `preview.py` | 标注画面 → letterbox 画布 → `show()`；屏幕触摸按钮；show 跑在主进程 daemon 线程 |
| `maixvision_stream.py` | MaixVision 图传（协议 0 客户端）；JPEG/WebSocket 在独立子进程 |
| `app_runtime.py` | 应用装配、三条时间轴调度、退出时按序释放硬件 |
| `camera_source.py` | MaixPy 帧 → 灰度 ndarray（灰度哑轴的坑见 `AGENTS.md` §6） |
| `rate_meter.py` / `telemetry.py` | 帧率计 / 周期日志拼装（无硬件依赖，可 PC 单测） |

## 6. 入口、配置与对外 API

- `main.py` 只做装配（几十行）；一切可调项在 `config.py`。
- `config.py` 末尾的 `apply_aim_profile(AIM_PROFILE)` 会在加载时**覆盖**六个增益/转速/限幅值——
  改手感先看它，别直接改被覆盖的字面值（机制详见 `AGENTS.md` §3.1）。
- `target_api.py` 是对外 API：`detect_black_frame` / `CenterTracker` / `AimLoop`，
  供其他小问直接复用，不依赖屏幕与云台硬件（云台部分可选）。

## 7. 上板与排障入口

- 板端日志 `[rect-center] <BUILD_ID>` 必须与本地逐字一致，否则跑的是旧代码；
- 屏幕右上角 `SELF-TEST` 按钮验证云台接线与方向（4 步动作）；
- `[perf]` 日志看各阶段耗时；帧率异常先查新鲜度门链路；
  未锁定时看行尾 `det_fail=full/<原因>`：`all_area` 是轮廓全被面积门淘汰（阈值或二值化），
  `all_filtered` 是有轮廓但没凑出合格四边形/长宽比，`no_proposal` 是二值图里没有轮廓——
  三者改法完全不同；分阶段调参见 `docs/视觉识别实现说明.md`；
- 排障手册：`存档/项目自检/` 三篇（硬件标定与上板检查 / 板端识别问题整理 / 板端故障排查）。
